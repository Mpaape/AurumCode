## Outcome

A documentacao do AurumCode vira um site pesquisavel e navegavel: busca de
texto completo que funciona offline (indice estatico), navegacao por
capacidade (Revisao, Skills e politica, Gate, Cadeia de suprimentos,
Qualquer linguagem, Benchmark, Operacao), paginas de referencia
(configuration.md, specs) e os tutoriais (AUR-561..564) no mesmo site. O
site e gerado por MkDocs Material numa imagem fixada por digest (um comando
local, sem instalar nada no host) e publicado no GitHub Pages por workflow
em cada push ao main, com actions fixadas por SHA. Nenhum conteudo novo
alem do indice e da navegacao: o card e a plataforma; os tutoriais sao os
cards seguintes.

## Public contract

- `mkdocs.yml` na raiz com `docs_dir: docs`, tema Material, idioma pt-BR,
  busca (plugin `search` com `lang: [pt]`), `navigation.tabs`,
  `navigation.indexes`, `content.code.copy`; `nav` explicito, agrupado por
  capacidade; a pagina inicial e `docs/index.md` (visao geral com links
  para cada capacidade e para os tutoriais).
- `scripts/docs/build.sh` gera o site com
  `docker run --rm -v "$PWD:/docs" <imagem squidfunk/mkdocs-material fixada
  por digest> build --strict` (warnings viram erro: link quebrado, pagina
  fora do nav, ancora inexistente). `scripts/docs/serve.sh` serve local.
- `.github/workflows/docs.yml`: em push ao main, constroi com a mesma imagem
  e publica no GitHub Pages (`actions/configure-pages`, `upload-pages-artifact`,
  `deploy-pages`, todos por SHA de commit confirmado com `gh api`);
  `permissions` minimos (`pages: write`, `id-token: write`) so no job de
  deploy; `--strict` tambem no CI.
- Aceite selado, offline: valida que todo `docs/**/*.md` (exceto specs, que
  entram por secao propria `Specs` gerada por glob ou listada) esta no
  `nav`; que todo link relativo interno resolve; que `mkdocs.yml` so cita
  arquivos existentes; que a imagem do build e por digest. A geracao real
  com o container fica registrada na spec com o log do `--strict`.

- O workflow legado `.github/workflows/pages.yml`, que publicava o guia
  manual de `docs/site` no mesmo ambiente github-pages, e removido: um unico
  workflow publica o site. `docs/site/workflow.yml` continua servido porque
  getting-started.md o referencia.

## Non-goals

Escrever tutoriais (AUR-561..564); hospedar fora do GitHub Pages.

## Acceptance scenarios

- AC-001: `scripts/docs/build.sh` gera o site com `--strict` sem warning (log na spec); o resultado tem indice de busca e navegacao por capacidade.
- AC-002: Toda pagina de `docs/` esta no `nav` e todo link interno resolve (aceite offline); pagina orfa ou link quebrado reprova.
- AC-003: O workflow usa a imagem por digest e actions por SHA, e so o job de deploy tem permissao de Pages.
- AC-004: `docs/index.md` cita cada capacidade entregue com link para a referencia e para o tutorial correspondente (teste compara com a lista de secoes de configuration.md).

## Skeptical mutations

- MUT-001: Remover uma pagina do `nav` reprova AC-002.
