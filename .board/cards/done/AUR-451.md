## Outcome

Revisar um pull request usa as mesmas capacidades da revisao local: passagem de seguranca, limiar de reprovacao, teto de custo e escolha de modelo valem com `--pr` como valem com `--base`.




## Achado medido (revisao de produto 2026-08-14)

`cmd/aurumcode/pr.go` NAO chama `SecurityScan` em lugar nenhum, e das flags
so usa `countAtOrAbove` internamente para o `--check`. Consequencia: no
caminho de PR — que e o caso de uso principal do produto — nao ha varredura
de seguranca, `--fail-on` nao vale, `--limite` nao vale e `--modelo` nao
vale. Todo o motor entregue nesta reconstrucao so funciona localmente.
O comentario do proprio pr.go declara isso como Non-goal do card que o
criou; este card remove essa limitacao. Compatibilidade: sem as flags
novas, a saida e o comportamento de `--pr` seguem byte-identicos.

## Review

- Reviewer: one independent reviewer reads the exact immutable candidate in a clean detached worktree, runs the declared command, and checks every changed hunk, the public contract, paths/read_paths, acceptance, declared selectors, mutations, profile/runtime compatibility, security boundaries, and exit-code handling.
