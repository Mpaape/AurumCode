## Outcome

Medido pelo Aurum no Aurum (2026-10-06): a PR #88 tem diff acima de 20000
linhas e a API do GitHub recusa o diff (`HTTP 406 too_large`); o review
falha fechado e nao revisa nada. E, numa PR de 111 arquivos (AUR-593),
6 arquivos ficaram fora do orcamento de tokens e o gate ficou
inconclusivo. Uma equipe real abre PRs assim (renomeacoes, geracao de
artefatos, limpezas grandes).

Com este card: (1) em `--pr`, quando a API recusa o diff por tamanho (ou
sempre, se for mais simples e seguro), o diff e calculado localmente a
partir do checkout verificado da PR (`base...head`, mesmo intervalo da
API), mantendo a verificacao de identidade do checkout (AUR-515/536);
(2) quando o conteudo revisavel passa do orcamento de um prompt, a sessao
revisa em lotes (agrupados por diretorio/pacote, cada lote com o mesmo
template, politica, skills e evidencia relevante aos arquivos do lote),
dentro de um teto de lotes e de custo da configuracao, e consolida os
achados num unico parecer e num unico gate; (3) so quando o teto e
atingido o review fica parcial, declarando os arquivos fora — nunca
aprova sem ter lido. Tutorial `revisao` ganha o caso de PR grande.

## Non-goals

Afrouxar o fail-closed; revisar arquivos ignorados ou binarios declarados; mudar o formato do parecer alem da indicacao de lotes.

## Acceptance scenarios

- AC-001: PR de fixture com diff acima do limite da API (servidor GitHub falso devolvendo 406 too_large): o review usa o diff local do checkout verificado e conclui; checkout nao verificado continua recusado.
- AC-002: Diff acima do orcamento de um prompt: revisao em N lotes, um parecer consolidado, todos os arquivos cobertos, gate unico; a auditoria registra os lotes.
- AC-003: Teto de lotes ou custo atingido: review parcial com os arquivos fora listados e aprovacao retida.
- AC-004: A propria PR #88 deste repositorio (ou um intervalo equivalente) e revisada por completo na imagem do produto.

## Skeptical mutations

- MUT-001: Tratar 406 como diff vazio reprova AC-001.
- MUT-002: Aprovar com lotes faltando reprova AC-003.
