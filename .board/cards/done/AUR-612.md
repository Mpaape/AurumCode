## Outcome

Pente fino de 2026-10-09 (revisores de arquitetura e de ferramentas
externas) achou texto que promete o que o codigo nao faz ou omite o passo que
faz o produto funcionar. Este card corrige so documentacao:

- camada 2 (padroes de engenharia centrais) nao e nativa: dizer como fazer hoje
  (pasta no repositorio da politica com CODEOWNERS, ou skills copiadas) e que
  nao existe segundo `policy_repository`;
- tabela de precedencia: `gate` sempre da politica; linhas para scanners,
  profiles, verification, deliberation, batches, changelog_check e
  dependencies; "cada secao de quality_gates e ignorada" corrigido;
- a politica nao fixa versao minima do AurumCode; o Dependabot atualiza so
  `uses:`, nunca `policy_ref`; tag para repositorio avulso, SHA para workflow
  obrigatorio da organizacao; como exigir o workflow (ruleset);
- o status `aurumcode/policy-gate` so impede merge com protecao de branch;
- PR do Dependabot so recebe Dependabot secrets;
- falha de `AURUMCODE_POLICY_TOKEN` aparece como erro do checkout;
- Bedrock/Azure como reserva exigem `LLM_FALLBACK_<n>_BASE_URL` no Actions;
  `LLM_API_KEY` precisa de valor mesmo para ollama;
- tabela de versoes fixadas das ferramentas (gitleaks, Semgrep, osv-scanner,
  Trivy, Cosign);
- o verificador adversarial aparece no fluxo de `docs/architecture.md`;
- o analista embutido de seguranca e uma passada do modelo, nao a varredura
  deterministica.
