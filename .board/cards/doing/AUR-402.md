## Outcome

um registry canônico associa cada profile key a schema, lock digest e image-set digest imutáveis; chave desconhecida, duplicada, não versionada ou tag mutável falha antes de qualquer engine.

## Non-goals

- Definir o conteúdo de qualquer profile concreto: `.board/oci/profiles/registry.v1.json` só indexa chave, schema, lock e image-set digest, e cada profile chega em seu próprio card.
- Agregar outro profile ou aceitar fallback para profile, lock ou imagem não registrados.

## Preconditions

- O artefato de schema de AUR-006 está presente e o pipeline estrutural está
  verde; a aprovação comportamental de AUR-006 não é necessária para validar o
  registry, que apenas referencia o schema como dado não confiável.
- O acceptance está selado e nenhuma credential ou valor de ambiente integra as fixtures.

## Postconditions

- um registry canônico associa cada profile key a schema, lock digest e image-set digest imutáveis; chave desconhecida, duplicada, não versionada ou tag mutável falha antes de qualquer engine.
- Nenhum engine é invocado para profile inválido e nenhum byte fora de `paths` muda.

## Acceptance scenarios

### AC-001: Versionar registry de perfis OCI

- Given: um registry nominal com duas entradas ordenadas e mutantes isolados para chave duplicada, profile sem versão, lock ausente e image tag mutável.
- When: o loader valida schema, ordenação, unicidade e digests sem consultar rede ou engine.
- Then: o nominal produz o mesmo registry digest; cada mutante retorna um código estável e nenhuma seleção parcial é aceita.
- Covers requirements: [PR-ARCH-001, PR-SEC-001, PR-SUP-001]
- Covers controls: [CR-EVD-001, CR-EVD-002, CR-EVD-003, CR-REV-001, CR-REV-002, CR-REV-003, CR-REV-004, CR-REV-005, CR-GATE-001, CR-TRUST-001, CR-TRUST-002, CR-TRUST-005]

## Security and privacy

- Registry, profile e locks são dados não confiáveis; somente digests e aliases públicos entram no artefato.
- Credentials, env, prompts, respostas, source privado e `AURUM_SECRET_CANARY` não entram em logs ou evidência.
- Validação ocorre antes do engine; nenhum profile concede autoridade, publicação, rede ou acesso ao host.

## Documentation

- `docs/specs/AUR-402.md` documenta schema, locks, imagens pinadas, comandos permitidos, limites, códigos e diagnóstico offline.

## Compatibility, migration, rollback

- Profiles existentes conservam chave e digest; mudança incompatível cria nova chave versionada.
- Migração altera consumidores por card dependente; nunca redireciona uma chave existente.
- Rollback remove somente esta entrada e seus arquivos quando nenhum consumidor depender dela.
