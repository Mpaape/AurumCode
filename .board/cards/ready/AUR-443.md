## Outcome

Um usuario que nunca leu o codigo-fonte descobre o que o comando faz e consegue rodar a primeira revisao: `aurumcode --help` lista os subcomandos, `aurumcode --version` existe, `--help` de cada subcomando sai no mesmo canal e com o mesmo exit code, e a mensagem de provider ausente mostra um exemplo concreto de fixture.


## Achados medidos (dogfooding 2026-08-13)

Nota de primeiro uso observada: 3/10. Concretamente:
- `aurumcode --help` e `-h` respondem `unknown command "--help"` com exit 2;
  nao ha ajuda de topo nem `version`/`--version`.
- `review --help` sai em stderr com exit 2; `docs --help` sai em stdout com
  exit 0 — mesmo binario, convencoes opostas.
- Sem provider, o primeiro comando falha com mensagem correta mas sem
  mostrar a FORMA de um arquivo de fixture nem apontar exemplo.
- A recusa por `--limite` sai 1, indistinguivel de "a ferramenta quebrou";
  `--fail-on` tem exit 3 dedicado.
- Erros de ref vazam interno do git e frase duplicada ("not a git
  repository: not a git repository (no .git dir ...)").
- O campo `summary` da resposta do modelo e parseado e nunca impresso.
- `docs --source` num projeto Python falha por `pydoc-markdown` ausente sem
  que o `--help` mencione o pre-requisito.
