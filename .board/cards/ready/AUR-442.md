## Outcome

Rodar a passagem de seguranca sobre um repositorio com segredo em texto puro aponta o segredo. Hoje 2 das 8 regras do catalogo tem matcher; `security/hardcoded-secret` nao tem nenhum, entao o proprio repo de demo do projeto (tests/fixtures/repos/git-demo, cujo unico proposito e plantar um segredo) devolve `No security findings.`


## Achado medido (dogfooding 2026-08-13)

Executando o binario real contra repositorios de verdade: `--seguranca` so
casa `security/sql-injection` e `security/command-injection`, e ambos exigem
a forma `"..." + var`. As outras seis regras (`xss`, `path-traversal`,
`hardcoded-secret`, `weak-crypto`, `insecure-random`, `missing-auth`) sao
metadados sem `pattern`, entao nunca casam nada. Consequencia observada: o
git-demo, que existe para plantar um segredo, sai `No security findings.`;
uma SQL injection escrita com f-string tambem escapa.

Duas saidas legitimas, escolha e documente: (a) dar `pattern` as regras
restantes, com fixtures que provem cada uma; ou (b) declarar honestamente no
`--help`, no spec e na saida que a passagem cobre um subconjunto nomeado, e
remover do catalogo (ou marcar como nao-executavel) o que nao casa nada.
Nao e aceitavel manter regra que promete deteccao e nunca dispara.

## Reparo de write-set (2026-08-13)

Corrigir o defeito quebra duas asserções que fixavam o comportamento
defeituoso: tests/acceptance/AUR-435.sh e tests/integration/AUR-435.go
afirmam "No security findings." sobre o git-demo, que existe justamente
para plantar um segredo. Mesmo precedente do AUR-424, cujo write-set foi
estendido para atualizar os testes que fixavam o contrato do gomarkdoc:
o card que muda o comportamento atualiza os testes que fixavam o antigo.
A atualização é rebasear a asserção para o comportamento correto, nunca
enfraquecê-la — o MUT-001 do AUR-435 (que roda sobre a fixture vuln)
precisa continuar mordendo.

## Review

- Reviewer: one independent reviewer reads the exact immutable candidate in a clean detached worktree, runs the declared command, and checks every changed hunk, the public contract, paths/read_paths, acceptance, declared selectors, mutations, profile/runtime compatibility, security boundaries, and exit-code handling.
- Independence: the reviewer is separate from the builder and does not edit the candidate or write evidence in the coordinator checkout. No extra review role is required.
- Verdict: approve only on raw exit 0 with real assertions. Runtime, loader, image, dependency, or other infrastructure failures are blocked or inconclusive, never approval.
