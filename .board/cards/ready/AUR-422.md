## Outcome

o profile bootstrap-readonly-v1 fixa imagem base por digest, usuário numérico não-root, rootfs read-only e rede negada, sem socket, mount, device ou capability, com no-new-privileges e tetos de wall-clock, memória, CPU, PIDs e bytes de stdout/stderr.

## Non-goals

- Alterar `.board/bin/oci-run` ou afrouxar seu `die 78`; `bootstrap-readonly-v1.json` apenas publica o documento de profile e o lock que o runner passa a resolver pelo registry.
- Agregar outro profile ou aceitar fallback para profile, lock ou imagem não registrados.

## Preconditions

- O schema de AUR-006 está aprovado e os inputs do registry são dados não confiáveis.
- O acceptance está selado e nenhuma credential ou valor de ambiente integra as fixtures.

## Postconditions

- o profile bootstrap-readonly-v1 fixa imagem base por digest, usuário numérico não-root, rootfs read-only e rede negada, sem socket, mount, device ou capability, com no-new-privileges e tetos de wall-clock, memória, CPU, PIDs e bytes de stdout/stderr.
- Nenhum engine é invocado para profile inválido e nenhum byte fora de `paths` muda.

## Acceptance scenarios

### AC-001: Definir perfil OCI bootstrap read-only

- Given: `bootstrap-readonly-v1.json` nominal com seu lock content-addressed, mais mutantes que ligam rede, tornam o rootfs gravável, elevam o usuário para uid 0 e removem o teto de bytes de stdout.
- When: o loader resolve a chave `bootstrap-readonly-v1` no registry e deriva o plano que `./.board/bin/oci-run` executaria antes de qualquer engine.
- Then: só o nominal deriva plano com rede negada, rootfs read-only, cap-drop total, no-new-privileges e uid diferente de zero; cada mutante retorna código estável e o runner nunca chega ao `die 78`.
- Covers requirements: [PR-ARCH-001, PR-SEC-001, PR-SUP-001]
- Covers controls: [CR-EVD-001, CR-EVD-002, CR-EVD-003, CR-REV-001, CR-REV-002, CR-REV-003, CR-REV-004, CR-REV-005, CR-GATE-001, CR-TRUST-001, CR-TRUST-002, CR-TRUST-005]

## Public contract

- Formaliza a chave `bootstrap-readonly-v1` já materializada pelo bootstrap, seu documento versionado, lock content-addressed e códigos de rejeição descritos neste TaskSpec, sem reescrever bytes nominais sem necessidade comprovada.
- `./.board/bin/oci-run` mantém o `die 78` para qualquer profile ausente do registry, e esta entrada não concede rede, mount, socket, device nem capability a consumidor algum.

## Security and privacy

- Registry, profile e locks são dados não confiáveis; somente digests e aliases públicos entram no artefato.
- Credentials, env, prompts, respostas, source privado e `AURUM_SECRET_CANARY` não entram em logs ou evidência.
- Validação ocorre antes do engine; nenhum profile concede autoridade, publicação, rede ou acesso ao host.

## Documentation

- `docs/specs/AUR-422.md` documenta a imagem pinada, o uid não-root, os tetos de wall-clock, memória, CPU, PIDs e stdout/stderr, os códigos de rejeição e o diagnóstico do `die 78`.

## Compatibility, migration, rollback

- Profiles existentes conservam chave e digest; mudança incompatível cria nova chave versionada.
- Migração altera consumidores por card dependente; nunca redireciona uma chave existente.
- Rollback remove somente esta entrada e seus arquivos quando nenhum consumidor depender dela.

## Review

- Reviewer: one independent reviewer reads the exact immutable candidate in a clean detached worktree and checks every changed hunk, the public contract, paths/read_paths, acceptance, declared selectors, mutations, profile/runtime compatibility, security boundaries, and exit-code handling.
- Independence: the reviewer is separate from the builder and does not edit the candidate or write evidence in the coordinator checkout. No extra review role is required.
- Verdict: approve only on raw exit 0 with real assertions. Runtime, loader, image, dependency, or other infrastructure failures are blocked or inconclusive, never approval. The validator reruns the declared acceptance on the same SHA when validation is not none.

## Evidence

Only the coordinator writes sanitized evidence under .board/evidence/<card-id>/; tests and builders emit observations only. Evidence binds the exact candidate SHA, review verdict, acceptance/validation exits, mutation result when declared, clean tree, and artifact hashes. Never store secrets, raw prompts/responses, credentials, environment values, or chain-of-thought.
