## Outcome

`review --pr --check` publica o status `aurumcode/review` no commit do HEAD do
pull request (o SHA revisado), nao no commit sintetico de merge que o GitHub
calcula. Sem isso, uma branch protection que exige o contexto `aurumcode/review`
nunca o ve (ele fica "expected") e a PR aparece instavel mesmo com o review
verde.

## Achado medido (2026-09-15)

Na release `dev -> main` (PR #36), o auto-review publicou
`check "aurumcode/review" publicado no commit f9f87af...: success`, onde
`f9f87af` e o merge sintetico do PR, nao o head `cd1eb53`. O head ficou sem o
status, a branch protection o marcou como "expected" e a PR so ficou `CLEAN`
depois de trocar o check exigido para o job do workflow. Causa: `GITHUB_SHA` e
reservado pelo Actions; o override no `review.yml` nao chega ao container, entao
`os.Getenv("GITHUB_SHA")` e o merge commit, nao o head.

## Non-goals

Nao mudar o veredito nem a politica de severidade. Nao publicar em `--base`
(uso local, sem PR). Nao usar `pull_request_target`.

- AC-001: com `--pr --check`, o status e definido no HEAD do PR obtido da API
