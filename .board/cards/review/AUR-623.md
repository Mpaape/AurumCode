## Outcome

Decisao do dono (2026-10-14): em repositorio PRIVADO sem GitHub Code Security
(sem aba Security para alertas de codigo), os achados do plugin agendado
viram issues do PROPRIO repositorio privado, visiveis so a colaboradores. Em
repositorio publico nunca: so a aba Security. Hoje (AUR-622) o job decide o
destino pela visibilidade e falha antes de rodar o plugin quando o destino
seria issues.

Depois deste card:

1. `aurumcode plugin issues --name N --sarif P --repo OWNER/REPO` sincroniza os
   achados do SARIF gerado pelo ingest com issues do repositorio: uma issue
   por achado, identificada por um marcador oculto com o fingerprint estavel
   (`<!-- aurumcode-plugin:<nome>:<fingerprint> -->`) e um rotulo
   `aurumcode-plugin:<nome>`; achado novo abre issue; achado que continua
   nao duplica (atualiza o corpo se mudou); issue aberta cujo achado sumiu de
   uma varredura CONCLUSIVA e fechada com comentario; issue fechada cujo
   achado volta e reaberta. Titulo e corpo em pt-BR legivel (regra, arquivo,
   linha, severidade, descricao redigida, sugestao), sem texto cru do modelo
   fora do corpo.
2. Recusa dura: o comando confere a visibilidade pela API e recusa (exit != 0,
   nada publicado) se o repositorio for publico ou se a visibilidade nao puder
   ser lida. Varredura inconclusiva (ingest sem SARIF) nao toca nas issues.
3. Job `plugins` do workflow reutilizavel: quando o destino e `issues`, roda
   o plugin e o ingest como hoje e depois `plugin issues` (permissao
   `issues: write` concedida pelo chamador); o log mostra so contagens
   (abertas, mantidas, fechadas, reabertas).

## Non-goals

Issues em repositorio publico; issues em outro repositorio; o aviso no gate
da PR; mudar o destino Security.

## Acceptance scenarios

- AC-001: SARIF com 2 achados contra um GitHub falso (servidor local) sem issues: abre 2 issues com marcador, rotulo e corpo legivel; segredo redigido.
- AC-002: rodada seguinte com 1 dos 2 e 1 novo: mantem 1 (sem duplicar), fecha o que sumiu com comentario, abre o novo; reabre issue fechada cujo achado volta.
- AC-003: repositorio publico ou visibilidade ilegivel: recusa com exit != 0 e nenhuma chamada de escrita; ingest inconclusivo: nenhuma chamada.
- AC-004: workflow: no destino issues o job roda plugin, ingest e plugin issues, sem upload-sarif, com issues: write documentado no chamador e log so com contagens.
- AC-005: tutorial plugin-agendado ganha o caso de destino issues (GitHub falso) e o caso de recusa em repo publico; run.sh all e --check verdes.
- MUT-001: abrir issue em repositorio publico faz AC-003 falhar.
- MUT-002: fechar issue com varredura inconclusiva faz AC-003 falhar.
