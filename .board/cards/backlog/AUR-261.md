## Outcome

a API retorna status sanitizado de um run autorizado e não expõe resume, cancel ou payload interno.

## Non-goals

- Oferecer resume, cancel ou qualquer mutação de run pela API, mesmo para principal autorizado.
- Publicação e credenciais, salvo quando explicitamente nomeadas no outcome.

## Preconditions

- os manifests aprovados de AUR-111, AUR-150, AUR-151 estão disponíveis na mesma base.
- Acceptance selado, árvore limpa e CandidateIdentityV1 completa.

## Postconditions

- a API retorna status sanitizado de um run autorizado e não expõe resume, cancel ou payload interno.
- Nenhum arquivo fora de `paths` ou capability não declarada muda.

## Acceptance scenarios

### AC-001: Expor runs por API read-only

- Given: um run `run-7f3a` já persistido pelo store de AUR-150/AUR-151 com stages concluídos, payload bruto do provider gravado no registro interno e um principal portador de escopo somente-leitura sobre esse run.
- When: um GET autorizado ao endpoint de runs é emitido uma vez e, em seguida, o mesmo endpoint recebe uma tentativa de resume por método mutável.
- Then: a resposta 200 contém apenas campos sanitizados de status, a tentativa mutável devolve 405 e `.board/evidence/AUR-261/acceptance/AC-001.json` mostra ausência de payload de provider no corpo.
- And: replay da mesma CandidateIdentityV1 é estruturalmente idêntico.
