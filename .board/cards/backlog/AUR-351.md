## Outcome

Um manifesto registra cada YAML de `.aurumcode/rules` com hash, schema status,
rule IDs, consumers e disposição, sempre `trusted=false` e `authority=none`.

## Non-goals

- Aplicar regra, alterar severity, suprimir finding ou conceder capability.
- Inventariar prompts/weights, que possuem cards independentes.

## Preconditions

- AUR-001 sela a árvore; AUR-009 e AUR-068 limitam sinks, schema e authority.
- Parser estrito recusa duplicate keys, anchors cíclicos e symlinks.

## Postconditions

- Cada arquivo/rule ID aparece uma vez com disposição explícita e sem values sensíveis.
- Source hash é preservado e nenhuma regra afeta review/config em execução.

## Acceptance scenarios

### AC-001: Manifestar rules como input não confiável

- Given: árvore hash-lockada e fixtures com duplicate ID, anchor e authority hostil.
- When: parser estático valida estrutura sem compor policy.
- Then: manifesto cobre todos os arquivos, registra schema status, `trusted=false` e `authority=none`.
- And: replay mantém hashes e nenhum finding muda.

- Covers requirements: [PR-ARCH-001, PR-CFG-002, PR-SKL-001]
- Covers controls: [CR-EVD-001, CR-EVD-002, CR-EVD-003, CR-REV-001, CR-REV-002, CR-REV-003, CR-REV-004, CR-REV-005, CR-GATE-001, CR-TRUST-001, CR-TRUST-002, CR-TRUST-004]

## Skeptical mutations

### MUT-001: AC-001 / repository

- Change: adicionar rule file após enumeração ou usar symlink escape.
- Expected: tree/manifest mismatch bloqueia antes da leitura externa.

### MUT-002: AC-001 / configuration

- Change: aceitar duplicate key/ID ou campo desconhecido silenciosamente.
- Expected: schema status falha closed e não grava linha aprovada.

### MUT-003: AC-001 / skill-policy

- Change: permitir rule sintética aprovar/suprimir review.
- Expected: authority probe detecta efeito e veta o manifesto.

## Security and privacy

- Data flow: estrutura/IDs/hashes -> TSV; values/bodies ficam fora de domínio/evidence.
- Secrets: canário sintético em value não aparece em sinks.
- Least privilege: read-only, zero policy composition/provider/tool/network.

## Documentation

- `docs/specs/AUR-351.md` define schema, trust semantics e disposições.

## Compatibility, migration, rollback

- Compatibility: rules permanecem byte-idênticas e não ativas.
- Migration: cada rule mantida requer schema/policy card explícito.
- Rollback: remover apenas derivados.

## Review

- Reviewer: one independent reviewer reads the exact immutable candidate in a clean detached worktree and checks every changed hunk, the public contract, paths/read_paths, acceptance, declared selectors, mutations, profile/runtime compatibility, security boundaries, and exit-code handling.
- Independence: the reviewer is separate from the builder and does not edit the candidate or write evidence in the coordinator checkout. No extra review role is required.
- Verdict: approve only on raw exit 0 with real assertions. Runtime, loader, image, dependency, or other infrastructure failures are blocked or inconclusive, never approval. The validator reruns the declared acceptance on the same SHA when validation is not none.

## Evidence

Only the coordinator writes sanitized evidence under .board/evidence/<card-id>/; tests and builders emit observations only. Evidence binds the exact candidate SHA, review verdict, acceptance/validation exits, mutation result when declared, clean tree, and artifact hashes. Never store secrets, raw prompts/responses, credentials, environment values, or chain-of-thought.
