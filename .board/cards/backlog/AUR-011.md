- Não agregar outro resultado implantável; expansões usam cards dependentes.

## Acceptance scenarios

### AC-001: Criar fixture Git demo determinística

- Given: `tests/specs/AUR-011/cases.yaml` contém vetores `nominal`, `invalid` e `boundary` para “Criar fixture Git demo determinística”, cada um com digest de entrada, saída ou erro esperado e limites do domínio; o harness rejeita mais de 64 vetores, 4 MiB totais ou deadline acima de 30 s.
- When: AC-001 executa “Criar fixture Git demo determinística” para cada vetor no perfil OCI pinado e captura `exit_code`, código de resultado ou erro, contagem de efeitos e digest do artifact.
- Then: o vetor `nominal` sai `0` e o artifact prova que o histórico sintético é recriado com os mesmos commits e somente segredos falsos.
- And: `invalid` e o primeiro valor além de `boundary` retornam erro tipado antes de efeito proibido; replay da mesma CandidateIdentityV1 preserva exit code, ordem e digest.

## Compatibility, migration, rollback

- Compatibility: contratos fora do Public contract permanecem inalterados; qualquer diferença não declarada falha AC-001.
- Migration: not-applicable neste card; migração de estado/legado exige card próprio.
- Rollback: reverter somente `paths`, remover artefatos derivados card-scoped e repetir AC-001 no base; nenhum estado externo é publicado por este card.

## Review

- Reviewer: one independent reviewer reads the exact immutable candidate in a clean detached worktree and checks every changed hunk, the public contract, paths/read_paths, acceptance, declared selectors, mutations, profile/runtime compatibility, security boundaries, and exit-code handling.
- Independence: the reviewer is separate from the builder and does not edit the candidate or write evidence in the coordinator checkout. No extra review role is required.
- Verdict: approve only on raw exit 0 with real assertions. Runtime, loader, image, dependency, or other infrastructure failures are blocked or inconclusive, never approval. The validator reruns the declared acceptance on the same SHA when validation is not none.

## Evidence

Only the coordinator writes sanitized evidence under .board/evidence/<card-id>/; tests and builders emit observations only. Evidence binds the exact candidate SHA, review verdict, acceptance/validation exits, mutation result when declared, clean tree, and artifact hashes. Never store secrets, raw prompts/responses, credentials, environment values, or chain-of-thought.
