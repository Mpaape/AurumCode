## Outcome

Duas builds limpas e offline da imagem funcional de AUR-226, com inputs idênticos, produzem o mesmo image digest, SBOM digest e provenance statement; relógio, ordem, uid/gid e path do host não alteram o resultado.

## Non-goals

- Publicar, assinar, implantar ou alterar o comportamento do servidor.
- Aceitar equivalência semântica quando qualquer digest de imagem, SBOM ou provenance divergir.

## Preconditions

- O contrato de release AUR-200, a imagem funcional AUR-226 e release-build-v1 estão aprovados para a mesma CandidateIdentityV1.
- Builder, base images, módulos, source epoch, plataformas e locks estão pinados e disponíveis offline.

## Postconditions

- O relatório contém os dois input manifests e compara image, config, layers, SBOM e provenance por digest.
- Divergência, fetch, secret request, timestamp variável ou falta de lock falha antes de qualquer publicação.

## Acceptance scenarios

### AC-001: Provar release OCI reproduzível

- Given: dois diretórios limpos com paths e mtimes diferentes, mas o mesmo source/locks, e um terceiro com exatamente um base digest alterado.
- When: release-build-v1 constrói os três sem rede e canonicaliza imagem, SBOM e provenance.
- Then: as duas builds equivalentes coincidem em todos os digests; a mutante falha como input drift e nenhum push ou credential é solicitado.
- Covers requirements: [PR-REL-001, PR-ARCH-001, PR-SUP-001]
- Covers controls: [CR-EVD-001, CR-EVD-002, CR-EVD-003, CR-REV-001, CR-REV-002, CR-REV-003, CR-REV-004, CR-REV-005, CR-GATE-001, CR-TRUST-001, CR-TRUST-005]

## Skeptical mutations

### MUT-001: AC-001 / repository

- Change: variar source path, mtime e ordem de arquivos sem alterar bytes.
- Expected: o mesmo `accept` continua verde e os digests permanecem iguais; se divergirem, a mutação falsifica a promessa.

### MUT-002: AC-001 / supply-chain

- Change: trocar exatamente um base image ou module lock digest.
- Expected: o mesmo `accept` falha com `AUR-421/AC-001/MUT-002/input-drift` antes do build nominal.

### MUT-003: AC-001 / container-engine

- Change: habilitar network fetch, secret mount, host bind ou push.
- Expected: o mesmo `accept` falha com `AUR-421/AC-001/MUT-003/unsafe-build`; nenhum destino externo é tocado.

## Security and privacy

- Build recebe somente source allowlisted e locks; nenhum credential, env herdado, socket ou host bind entra no worker.
- SBOM e provenance contêm aliases/digests públicos e paths normalizados, nunca paths privados ou source secreto.
- Artefatos permanecem locais e não assinados; publicação é outro gate autorizado.

## Compatibility, migration, rollback

- AUR-226 continua responsável pela imagem funcional; esta prova apenas adiciona propriedades de release.

- Rollback remove a prova sem promover build não reproduzível ou publicar artefato.

## Review

- Reviewer: one independent reviewer reads the exact immutable candidate in a clean detached worktree and checks every changed hunk, the public contract, paths/read_paths, acceptance, declared selectors, mutations, profile/runtime compatibility, security boundaries, and exit-code handling.
- Independence: the reviewer is separate from the builder and does not edit the candidate or write evidence in the coordinator checkout. No extra review role is required.
- Verdict: approve only on raw exit 0 with real assertions. Runtime, loader, image, dependency, or other infrastructure failures are blocked or inconclusive, never approval. The validator reruns the declared acceptance on the same SHA when validation is not none.

## Evidence

Only the coordinator writes sanitized evidence under .board/evidence/<card-id>/; tests and builders emit observations only. Evidence binds the exact candidate SHA, review verdict, acceptance/validation exits, mutation result when declared, clean tree, and artifact hashes. Never store secrets, raw prompts/responses, credentials, environment values, or chain-of-thought.
