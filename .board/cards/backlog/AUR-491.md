## Outcome

Um dev que nunca viu o projeto liga o code review no repositorio dele copiando
o que esta escrito. A revisao de 2026-09-13 mediu a doc como CONFUSA: capacidades
anunciadas so no caminho `--pr`; `review.memory` no-op local; `@v1` descrito
como "versao anterior" quando e OUTRO produto (gerador de documentacao Jekyll,
`action.yml` incompativel); `fix` sem exemplo executavel; `--limite`, `--modelo`,
`AURUMCODE_LLM_INPUT_USD_PER_1K`, `AURUMCODE_LLM_OUTPUT_USD_PER_1K`,
`AURUMCODE_GITHUB_API_URL` e `AURUMCODE_CACHE_DIR` sem doc; README sem indice
e com o guia escondido em "Executar e desenvolver".

## Acceptance

- AC-001 Nada sem doc. O script deriva do codigo a lista de flags
  (`flag.` em `cmd/aurumcode/*.go`) e de variaveis (`os.Getenv`/`LookupEnv` com
  prefixo `AURUMCODE_`/`LLM_`/`GITHUB_` em `cmd` e `internal`) e exige cada uma
  em `docs/configuration.md`. Lista derivada, nunca fixa.
- AC-002 Fix executavel. `docs/getting-started.md` traz a sequencia
  review -> arquivo de sugestoes -> `aurumcode fix --file ...` e o script a
  executa no container contra a fixture com exit 0 e patch nao vazio.
- AC-003 Comece aqui. As primeiras 30 linhas do README dizem o que o produto
  faz, que e gratuito e open source, linkam `docs/getting-started.md` como
  primeiro passo, e declaram em uma frase que `@v1` e o antigo gerador de
  documentacao e que o code review comeca em `v2`. Ha um indice.
- AC-004 Sem promessa de caminho unico. Toda capacidade listada em "Capacidades"
  do README tem, em `docs/getting-started.md`, o comando que a exercita
  localmente (o script casa os nomes das capacidades com as secoes do guia).
