## Outcome

Um fake `POST /v1/responses` valida o request unary Responses API declarado e
devolve exatamente um response completo com output e usage canônicos.

## Non-goals

- Chat Completions, streaming, tool calls, background mode ou estado de conversation.
- Coagir input Chat para Responses ou realizar downgrade silencioso.

## Preconditions

- Contratos AUR-055/AUR-057 aprovados e fault executor AUR-350 disponível na mesma identidade.
- Fixture contém apenas conteúdo sintético e endpoint loopback.

## Postconditions

- Request nominal retorna um `response.completed` unary representado pelo golden versionado.
- Capability ou campo fora do subset falha antes de produzir output.

## Acceptance scenarios

### AC-001: Responder Responses API unary

- Given: `tests/specs/AUR-342/cases.yaml` fixa `model`, array `input`, `max_output_tokens=64`, output_text esperado, campo desconhecido, `stream=true` e body maior que 64 KiB; deadline é 5 s.
- When: o client envia cada body para `/v1/responses` e captura request digest, status, error code, response digest e quantidade de outputs.
- Then: nominal retorna 200, `status=completed`, um output message e usage exato; campo desconhecido, streaming e oversize retornam `unsupported_responses_field`, `stream_capability_required` e `request_too_large` antes de qualquer output.
- And: repetir nominal preserva IDs sintéticos, ordenação e digest; nenhuma chamada alcança rede externa ou credential resolver.

- Covers requirements: [PR-ARCH-001, PR-LLM-001, PR-LLM-002]
- Covers controls: [CR-EVD-001, CR-EVD-002, CR-EVD-003, CR-REV-001, CR-REV-002, CR-REV-003, CR-REV-004, CR-REV-005, CR-GATE-001, CR-TRUST-002, CR-TRUST-004]
