## Outcome

Um manifesto TSV ordenado registra cada arquivo de `.aurumcode/prompts` com
hash, purpose, consumers, disposição e `trusted=false`, sem inserir o corpo em
contexto de agente nem executá-lo.

## Non-goals

- Carregar prompt, chamar modelo, conceder tool, aprovar review ou editar os arquivos.
- Inventariar rules, bash docs ou metadata `.aurumcode`, separados em AUR-351..354.

## Preconditions

- AUR-001 sela a árvore, AUR-009 define sinks e AUR-068 fornece o schema/capability policy.
- Apenas arquivos regulares sob o root exato são enumerados; symlinks e novos tipos bloqueiam.

## Postconditions

- Cada prompt observado tem uma linha content-addressed e `trusted=false`, com zero bodies no output.
- A árvore de prompts conserva o hash agregado e nenhum provider/tool foi invocado.

## Acceptance scenarios

### AC-001: Manifestar prompts sem ativá-los

- Given: árvore hash-lockada com nested prompt e fixture hostil sintética.
- When: enumerador lexical produz metadados bounded em ordem bytewise.
- Then: todos os prompts aparecem com disposição e `trusted=false`, sem body ou process invocation.
- And: replay produz o mesmo digest e source hash.

- Covers requirements: [PR-ARCH-001, PR-SKL-001]
- Covers controls: [CR-EVD-001, CR-EVD-002, CR-EVD-003, CR-REV-001, CR-REV-002, CR-REV-003, CR-REV-004, CR-REV-005, CR-GATE-001, CR-TRUST-001, CR-TRUST-002, CR-TRUST-004]

## Skeptical mutations

### MUT-001: AC-001 / repository

- Change: adicionar prompt nested após a enumeração ou substituir arquivo por symlink.
- Expected: tree/manifest digest diverge e AC-001 falha antes de ler o alvo.

### MUT-002: AC-001 / skill-policy

- Change: marcar prompt sintético como trusted ou permitir que aprove resultado.
- Expected: capability/trust gate veta a linha e nenhum prompt é executado.

## Security and privacy

- Data flow: paths/hashes/classificação -> TSV; bodies ficam fora de prompt, log e evidence.
- Secrets: canário sintético no body é ausente de todos os sinks.
- Least privilege: checkout read-only, allowlist de root, zero provider/tool/network.

## Documentation

- `docs/specs/AUR-334.md` define schema, untrusted semantics e card posterior por disposição.

## Compatibility, migration, rollback

- Compatibility: prompts existentes permanecem byte-idênticos e não endossados.
- Migration: cada prompt keep/migrate exige skill/provider contract separado.
- Rollback: apagar somente manifest/docs/evidence derivados.

## Review

- Reviewer: one independent reviewer reads the exact immutable candidate in a clean detached worktree and checks every changed hunk, the public contract, paths/read_paths, acceptance, declared selectors, mutations, profile/runtime compatibility, security boundaries, and exit-code handling.
- Independence: the reviewer is separate from the builder and does not edit the candidate or write evidence in the coordinator checkout. No extra review role is required.
- Verdict: approve only on raw exit 0 with real assertions. Runtime, loader, image, dependency, or other infrastructure failures are blocked or inconclusive, never approval. The validator reruns the declared acceptance on the same SHA when validation is not none.

## Evidence

Only the coordinator writes sanitized evidence under .board/evidence/<card-id>/; tests and builders emit observations only. Evidence binds the exact candidate SHA, review verdict, acceptance/validation exits, mutation result when declared, clean tree, and artifact hashes. Never store secrets, raw prompts/responses, credentials, environment values, or chain-of-thought.
