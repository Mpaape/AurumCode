## Outcome

cada `uses:` local ou remoto aparece uma vez; ação remota resolve para commit SHA completo, enquanto action local vincula source digest e não há branch/tag mutável.

## Non-goals

- Atualizar os workflows para versões novas de action ou reescrever um `uses:` mutável; o card apenas registra em `actions.yml` as referências já presentes e falha quando divergem.
- Agregar os resultados irmãos; o card pai verifica o conjunto em etapa separada.

## Preconditions

- As dependências `[AUR-359]` estão aprovadas na mesma CandidateIdentityV1, quando não vazio.
- A fixture `tests/bootstrap/locks/AUR-361/cases.tsv` contém nominal, ausência, symlink/tamper e primeiro valor acima do limite; nenhuma entrada contém credencial real.

## Postconditions

- cada `uses:` local ou remoto aparece uma vez; ação remota resolve para commit SHA completo, enquanto action local vincula source digest e não há branch/tag mutável.
- O input observado e todos os paths fora de `paths` permanecem byte-idênticos; não há processo, rede ou secret sink não declarado.

## Acceptance scenarios

### AC-001: Fixar referências de GitHub Actions

- Given: `tests/bootstrap/locks/AUR-361/cases.tsv` sela source/input digests, resultados e códigos esperados, limitada a 256 entradas, 4 MiB e 15 s.
- When: `VerifyBootstrapLockV1` cruza cada `uses:` dos workflows com `.board/bootstrap/locks/actions.yml`, exigindo commit SHA completo para action remota e source digest para action local, sem resolver referência pela rede.

## Skeptical mutations

### MUT-001: AC-001 / repository

- Change: adicionar uma linha `uses:` ao workflow sem atualizar o lock.
- Expected: o aceite sai 1 com `AUR-361/AC-001/action-unlocked`; restore recupera cobertura bidirecional.

### MUT-002: AC-001 / scm

- Change: substituir um commit SHA de action por tag `v5`.
- Expected: o aceite sai 1 com `AUR-361/AC-001/action-ref-mutable`; restore exige SHA completo.

### MUT-003: AC-001 / supply-chain

- Change: alterar o owner/repository mantendo o SHA anterior.
- Expected: o aceite sai 1 com `AUR-361/AC-001/action-identity-mismatch`; restore vincula identidade e digest.

## Security and privacy

- Data flow: ações usadas pelo composite action e workflows -> parser/probe bounded -> digests, counts, status e disposition sanitizados.
- Secrets: `AURUM_SECRET_CANARY` e valores credential-shaped não aparecem em stdout, stderr, manifest, logs ou evidence; somente classes/counts são permitidas.
- Least privilege: worker non-root, rootfs e checkout read-only, rede none, capabilities ALL dropped, no-new-privileges, PIDs/memória/CPU/deadline bounded; nenhuma publicação.
