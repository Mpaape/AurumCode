## Outcome

`FaultScriptV1` executa uma sequência provider-neutral bounded sobre relógio
virtual e produz o mesmo status/body/chunk/close trace para a mesma seed.

## Non-goals

- Implementar rota ou wire format de qualquer provider, retry policy ou sleep real.
- Ler rede, ambiente, credencial ou relógio de parede para decidir o trace.

## Preconditions

- AUR-055 define erros/cancel canônicos e AUR-057 define transporte/response bounds.
- Scripts e seeds são fixtures sintéticas ligadas à CandidateIdentityV1.

## Postconditions

- Ações allowlisted `status`, `body`, `chunk`, `delay_virtual` e `close` executam em ordem e terminam bounded.
- Script inválido/oversize/over-delay falha antes de escrever resposta parcial.

## Acceptance scenarios

### AC-001: Reproduzir fault trace sem tempo real

- Given: `tests/specs/AUR-350/cases.yaml` fixa seed 7 e scripts separados para 429+Retry-After, 503, malformed body, 1 MiB body, timeout virtual, connection close e cancel; máximo 16 actions, 1 MiB total e 5 s virtuais.
- When: `ExecuteFaultScript` roda cada script duas vezes com fake clock e registra action index/type, virtual timestamp, status/body/chunk digest, terminal reason e real elapsed bound.
- Then: as duas execuções são estruturalmente idênticas; unknown action, 17 actions, body 1 MiB+1 e delay 5 s+1 retornam `unknown_fault_action`, `too_many_fault_actions`, `fault_body_too_large` e `fault_delay_too_large` antes do primeiro write.
- And: cancel interrompe no action index selado, `real_elapsed<1s`, pending timers/handlers voltam a zero e nenhum provider-specific campo entra no trace.

- Covers requirements: [PR-ARCH-001, PR-LLM-001]
- Covers controls: [CR-EVD-001, CR-EVD-002, CR-EVD-003, CR-REV-001, CR-REV-002, CR-REV-003, CR-REV-004, CR-REV-005, CR-GATE-001, CR-TRUST-002, CR-TRUST-004]

## Security and privacy

- Data flow: scripts sintéticos -> validator/executor virtual -> digests/timestamps/counts.
- Secrets: body com canário é rejeitado e nunca persistido; nenhum env/header/provider payload é lido.
- Least privilege: sem egress, real clock dependency, shell, credential, host mount ou engine socket.

## Documentation

- `docs/specs/AUR-350.md` documenta schema, actions, bounds, prevalidation, cancel e fake-clock contract.

## Compatibility, migration, rollback

- Compatibility: consumers dependem somente do schema versionado provider-neutral.
- Migration: novos fault types exigem nova schema version e capability explícita.
- Rollback: remover action nova e fixtures antes de retirar versão; executor não persiste estado.

## Review

- Reviewer: one independent reviewer reads the exact immutable candidate in a clean detached worktree and checks every changed hunk, the public contract, paths/read_paths, acceptance, declared selectors, mutations, profile/runtime compatibility, security boundaries, and exit-code handling.
- Independence: the reviewer is separate from the builder and does not edit the candidate or write evidence in the coordinator checkout. No extra review role is required.
- Verdict: approve only on raw exit 0 with real assertions. Runtime, loader, image, dependency, or other infrastructure failures are blocked or inconclusive, never approval. The validator reruns the declared acceptance on the same SHA when validation is not none.

## Evidence

Only the coordinator writes sanitized evidence under .board/evidence/<card-id>/; tests and builders emit observations only. Evidence binds the exact candidate SHA, review verdict, acceptance/validation exits, mutation result when declared, clean tree, and artifact hashes. Never store secrets, raw prompts/responses, credentials, environment values, or chain-of-thought.
