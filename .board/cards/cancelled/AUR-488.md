## Outcome

Ao gerar documentacao de outro projeto, a pagina inicial apresenta aquele
projeto e sua API, com apresentacao bonita e navegacao responsiva. Uma pagina
inicial autoral e preservada sem tutorial duplicado do AurumCode.

## Evidencia do problema

writeIndex em internal/documentation/site/scaffold.go injeta renderQuickstartBlock
incondicionalmente. O bloco ensina clonar o AurumCode e descreve limites do seu
review mesmo ao documentar outro projeto. No site oficial ele duplica a jornada
autoral. O usuario pediu paginas bonitas e produto ergonomico; o conteudo deve
servir ao leitor do projeto documentado.

## Non-goals

- Nao inventar comandos de instalacao/uso do projeto documentado.
- Nao mudar extractors, credenciais, regras de review nem publicacao.
- Nao sobrescrever estilos, layouts ou configuracao autorais existentes.
- Nao exigir LLM, fontes remotas ou biblioteca de UI para apresentar o site.

## Acceptance scenarios

- AC-001: um projeto fixture de nome distinto gera index com identidade do
  projeto e acesso a referencia real. Nao inclui git clone do AurumCode nem
  tutorial ou limites de code review alheios ao projeto.
- AC-002: com index autoral, titulo/frontmatter/conteudo sao preservados;
  somente blocos gerados sao atualizados. Repetir geracao nao duplica secoes.
- AC-003: scaffold novo ganha layout e CSS locais responsivos, links que
  respeitam baseurl, codigo legivel e navegacao a API. Arquivos autorais de
  mesmo nome sao preservados; nao copiar nenhum segredo/contexto interno.
- AC-004: build Jekyll em container e navegador sobre projeto gerado, em
  1440px e 390px, provam navegacao funcional, assets existentes e ausencia
  de overflow global. Site oficial conserva apresentacao do AUR-487.

## Public contract

URLs e paginas de API preservadas. O tutorial de produto pertence ao site
oficial/guia; deixa de ser injetado no projeto consumidor. Atualizar testes
anteriores que exigiam essa injecao, preservando provas de navegação,
contagem, separacao da referencia e idempotencia.
