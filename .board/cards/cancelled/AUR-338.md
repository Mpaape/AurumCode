## Outcome

`.docker/docs.Dockerfile` e `.docker/README.md` recebem manifesto estático com
hash e disposição `quarantine-no-build`; FROM/ADD/COPY/USER/entrypoint são
auditados sem build, pull, rede ou execução de stage.

## Non-goals

- Construir a imagem, corrigir o Dockerfile, selecionar site generator ou substituir o Dockerfile raiz de AUR-303.
- Confiar em instruções do README como supply-chain provenance.

## Preconditions

- AUR-001 fixa os dois arquivos, AUR-009 fornece canários e AUR-233 define locks permitidos antes de qualquer uso.
- O parser recebe somente bytes locais e não chama Docker, Podman ou registry.

## Postconditions

- O manifesto contém as duas superfícies e `quarantine-no-build`, com findings estáticos bounded e `static_audit=pass` somente quando o parser conclui.
- Zero imagem, container, network request ou source modification é produzido.

## Acceptance scenarios

### AC-001: Auditar e quarentenar sem build

- Given: hashes selados e fixtures com tag mutável, remote ADD, root user e instrução README hostil.
- When: o parser estático enumera instruções e cruza referências com locks locais.
- Then: ambos paths são mapeados, o Dockerfile fica `quarantine-no-build` e nenhuma engine é invocada.
- And: replay preserva source hashes e manifesto digest.

- Covers requirements: [PR-ARCH-001, PR-REL-001, PR-SEC-001, PR-SUP-001]
- Covers controls: [CR-EVD-001, CR-EVD-002, CR-EVD-003, CR-REV-001, CR-REV-002, CR-REV-003, CR-REV-004, CR-REV-005, CR-GATE-001, CR-TRUST-001, CR-TRUST-004, CR-TRUST-005]

## Skeptical mutations

### MUT-001: AC-001 / repository

- Change: trocar fixture regular por symlink para Dockerfile fora da árvore permitida.
- Expected: path resolver falha antes do parse e AC-001 veta a evidência.

### MUT-002: AC-001 / supply-chain

- Change: inserir `FROM ...:latest` ou remote `ADD` em fixture e marcar audit pass.
- Expected: lock/static policy detecta a violação e o acceptance falha.

### MUT-003: AC-001 / container-engine

- Change: chamar Docker/Podman build durante o audit.
- Expected: process canary invalida no-build mesmo que a análise textual esteja correta.

## Security and privacy

- Data flow: instruções tokenizadas/hashes -> finding IDs/manifest; build context e README body não viram engine input.
- Secrets: nenhum build arg/env/secret é resolvido; canário sintético não sai do parser.
- Least privilege: no engine socket/process, no network/pull, checkout read-only e bounded parser.

## Documentation

- `docs/specs/AUR-338.md` registra findings, quarentena e precondições de um replacement seguro.

## Compatibility, migration, rollback

- Compatibility: fontes e imagens existentes não são alteradas nem endossadas.
- Migration: replacement posterior deve provar equivalência e supply-chain antes de remover a quarentena.
- Rollback: remover derivados; nunca desfazer quarentena executando o legado.

## Review

- Reviewer: one independent reviewer reads the exact immutable candidate in a clean detached worktree and checks every changed hunk, the public contract, paths/read_paths, acceptance, declared selectors, mutations, profile/runtime compatibility, security boundaries, and exit-code handling.
- Independence: the reviewer is separate from the builder and does not edit the candidate or write evidence in the coordinator checkout. No extra review role is required.
- Verdict: approve only on raw exit 0 with real assertions. Runtime, loader, image, dependency, or other infrastructure failures are blocked or inconclusive, never approval. The validator reruns the declared acceptance on the same SHA when validation is not none.

## Evidence

Only the coordinator writes sanitized evidence under .board/evidence/<card-id>/; tests and builders emit observations only. Evidence binds the exact candidate SHA, review verdict, acceptance/validation exits, mutation result when declared, clean tree, and artifact hashes. Never store secrets, raw prompts/responses, credentials, environment values, or chain-of-thought.
