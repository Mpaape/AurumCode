## Outcome

O fake Chat valida uma tool allowlisted com JSON Schema estrito e devolve um
único `tool_calls` golden cujos argumentos são JSON válido e byte-estável.

## Non-goals

- Executar a tool, emitir stream, aceitar escolha automática fora da fixture ou reutilizar formato Responses.
- Corrigir argumentos inválidos ou permitir nome/schema não allowlisted.

## Preconditions

- Tool contract AUR-055, transporte AUR-057 e fault executor AUR-350 aprovados.
- A fixture não disponibiliza shell, MCP, filesystem ou secret channel.

## Postconditions

- Request nominal produz finish_reason `tool_calls` e exatamente uma chamada `lookup_symbol`.
- Schema/nome inválido falha antes de qualquer execução, com `tool_executions=0`.

## Acceptance scenarios

### AC-001: Emitir Chat tool_calls sem executar tool

- Given: `tests/specs/AUR-347/cases.yaml` define tool `lookup_symbol` com object schema, required `symbol`, argumentos `{"symbol":"Review"}`, nome desconhecido, schema permissivo e argumentos acima de 8 KiB.
- When: o client envia a declaração e registra tool-definition digest, status, finish reason, call ID/name/arguments digest e execution count.
- Then: nominal retorna uma call allowlisted com JSON arguments válido; unknown, non-strict e oversize retornam `tool_not_allowed`, `tool_schema_not_strict` e `tool_arguments_too_large`.
- And: `tool_executions=0` para todos os casos, call ID/digest são determinísticos e nenhum capability externo é solicitado.

- Covers requirements: [PR-ARCH-001, PR-LLM-001, PR-LLM-002]
- Covers controls: [CR-EVD-001, CR-EVD-002, CR-EVD-003, CR-REV-001, CR-REV-002, CR-REV-003, CR-REV-004, CR-REV-005, CR-GATE-001, CR-TRUST-002, CR-TRUST-004]

## Security and privacy

- Data flow: schemas/args sintéticos -> fake loopback -> digests/counts.
- Secrets: tool args com canário são rejeitados; raw args não persistem.
- Least privilege: nenhuma tool capability, shell, rede externa ou host access.

## Review

- Reviewer: one independent reviewer reads the exact immutable candidate in a clean detached worktree and checks every changed hunk, the public contract, paths/read_paths, acceptance, declared selectors, mutations, profile/runtime compatibility, security boundaries, and exit-code handling.
- Independence: the reviewer is separate from the builder and does not edit the candidate or write evidence in the coordinator checkout. No extra review role is required.
- Verdict: approve only on raw exit 0 with real assertions. Runtime, loader, image, dependency, or other infrastructure failures are blocked or inconclusive, never approval. The validator reruns the declared acceptance on the same SHA when validation is not none.

## Evidence

Only the coordinator writes sanitized evidence under .board/evidence/<card-id>/; tests and builders emit observations only. Evidence binds the exact candidate SHA, review verdict, acceptance/validation exits, mutation result when declared, clean tree, and artifact hashes. Never store secrets, raw prompts/responses, credentials, environment values, or chain-of-thought.
