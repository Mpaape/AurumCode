GitHub Actions gratuito open source

Code review de pull request,
publicado pelo seu próprio GitHub Actions.

A cada PR, o AurumCode roda um code review completo: analisa segredo, SQL e command injection sem configurar nada, resume a mudança e comenta na linha certa. Gratuito e open source — o workflow roda dentro da sua própria conta, com seu modelo.

DO REPOSITÓRIO AO PRIMEIRO PARECER

Três passos, nenhum servidor para manter

  1. 1

    Adicione o workflow

    Cole o YAML da seção Instalar em .github/workflows/aurumcode.yml, na branch base do repositório.

  2. 2

    Configure os secrets

    Em Settings → Secrets and variables → Actions, adicione LLM_API_KEY e LLM_BASE_URL do seu endpoint compatível com OpenAI.

  3. 3

    Abra um pull request

    O job roda a cada novo commit do PR e publica comentário, resumo e diagrama na aba Conversation.

O QUE JÁ ESTÁ NO BINÁRIO

Oito capacidades, zero serviço adicional

Sugestão de 1 clique

Comentários ancorados na linha alterada (--na-linha). Quando o GitHub reconhece a substituição, oferece aplicar — o autor decide.

Resumo e diagrama

Todo PR recebe um TL;DR e um fluxograma Mermaid do que mudou, gerado a partir do próprio diff, sem configurar nada.

Análise determinística

Segredo, SQL e command injection são checados em toda revisão. --seguranca soma XSS e o catálogo completo de 8 regras.

Contexto de codebase

O parecer aponta o que mais a mudança pode afetar no repositório, além do diff isolado — por heurística, não por índice completo.

Memória por repositório

Notas de revisão persistem entre execuções (review.memory: local). Observação para o próximo round — nunca aprovação automática.

Fix por CLI

aurumcode fix converte as sugestões publicadas em um patch aplicável, sem depender da interface do GitHub.

Custo sob controle

--limite estima o gasto antes de chamar o modelo e recusa a chamada acima do teto — sem gastar nada nesse caso.

Modelo agnóstico

Qualquer endpoint compatível com OpenAI. Configure LLM_BASE_URL, LLM_API_KEY e, se precisar, LLM_MODEL.

LIMITES

Escopo objetivo

Review do diff do PR. Com provedor, análise semântica; sem provedor, somente baseline offline. review.memory: local exige cache entre jobs; cada execução reavalia o PR inteiro.

COMO USAR CADA RECURSO

Ativa, funciona, exemplo

Sem provedor configurado, só o baseline determinístico roda. Com provedor, cada capacidade abaixo consome tokens do seu modelo — cada card marca o que é padrão, o que é opcional e o que custa.

Análise determinística ligado por padrão

  1. Ativa

    Já roda em todo review, sem nenhum arquivo. No workflow reutilizável o catálogo completo já vem com security: true (padrão); na CLI local, adicione --seguranca.

  2. Como funciona

    Cada linha adicionada passa por matchers determinísticos — segredo, SQL e command injection; com o passe completo, também XSS e o resto do catálogo. Sem modelo, sem custo de LLM.

  3. Exemplo
    aurumcode review --base HEAD~1 --seguranca

Resumo + diagrama ligado por padrão

  1. Ativa

    Já roda em todo review com provedor, sem flag e sem arquivo.

  2. Como funciona

    O modelo resume a mudança (TL;DR) e desenha o fluxo alterado em Mermaid, direto do diff. Entra no custo de tokens do seu provedor.

  3. Exemplo

    Nada para copiar — aparece no comentário do PR.

Contexto de codebase ligado por padrão

  1. Ativa

    Já roda por heurística: arquivos próximos ao diff entram no prompt, sem índice do repositório.

  2. Como funciona

    O parecer pode apontar efeitos além do diff isolado. Aumenta tokens — para direcionar, liste arquivos em review.context.

  3. Exemplo
    # .aurumcode/config.yml
review:
  context:
    skills:
      - .aurumcode/skills/backend.md
    docs:
      - docs/architecture.md

Sugestão de 1 clique opcional

  1. Ativa

    Desligado por padrão. Ative no workflow (inline_comments: true) ou no .aurumcode/config.yml.

  2. Como funciona

    Achados elegíveis viram comentários na linha alterada; no review formal, o GitHub oferece aplicar a substituição — o autor decide. Redigir cada sugestão consome tokens.

  3. Exemplo
    # .aurumcode/config.yml
review:
  inline_comments: true

Memória por repositório opcional

  1. Ativa

    Desligado por padrão (off). Ative com review.memory: local no .aurumcode/config.yml.

  2. Como funciona

    Guarda observações de revisões anteriores no cache para reduzir repetição — nunca muda regras, severidade ou veredito. Em runner efêmero, cacheie o diretório entre jobs.

  3. Exemplo
    # .aurumcode/config.yml
review:
  memory: local

Fix por CLI CLI local

  1. Ativa

    Fora do GitHub, na sua máquina: o binário local lê a revisão publicada e gera o patch.

  2. Como funciona

    aurumcode fix converte as sugestões da revisão em um diff unificado aplicável. Você inspeciona e aplica; nada é escrito no repositório sozinho.

  3. Exemplo
    docker run --rm aurumcode:local fix < review-response.json > fix.patch
git apply --check fix.patch

Custo sob controle opcional

  1. Ativa

    Sem teto por padrão. Defina o teto em dólar com --limite na execução local.

  2. Como funciona

    O comando estima o custo antes de chamar o modelo; se a estimativa passar do teto, recusa — sem gastar nada.

  3. Exemplo
    docker run --rm aurumcode:local review --base HEAD~1 --limite 0.50

Modelo agnóstico opcional

  1. Ativa

    Sem LLM_MODEL, o serviço escolhe o modelo dele. Defina o endpoint com variáveis de ambiente.

  2. Como funciona

    Qualquer endpoint compatível com OpenAI, inclusive local. O nome do modelo entra no cálculo de custo junto com --limite.

  3. Exemplo
    export LLM_BASE_URL=http://127.0.0.1:8080/v1
export LLM_API_KEY=your-api-key
export LLM_MODEL=your-model

DO ZERO AO PRIMEIRO REVIEW

Cole um arquivo, adicione dois secrets

Nenhuma conta nova, nenhum serviço para assinar: o workflow abaixo roda no runner do próprio GitHub, com o binário publicado nesta tag.

.github/workflows/aurumcode.yml
name: Code review
on:
  pull_request:
    types: [opened, synchronize, reopened]
permissions:
  contents: read
  pull-requests: write
  statuses: write
  checks: read
jobs:
  review:
    uses: Mpaape/AurumCode/.github/workflows/review.yml@v2
    with:
      model: ${{ vars.LLM_MODEL }}
    secrets:
      LLM_API_KEY: ${{ secrets.LLM_API_KEY }}
      LLM_BASE_URL: ${{ secrets.LLM_BASE_URL }}

Em Settings → Secrets and variables → Actions, adicione LLM_API_KEY e LLM_BASE_URL do seu endpoint compatível com OpenAI; LLM_MODEL é opcional, use se o serviço exigir um nome de modelo. Secrets do repositório não ficam disponíveis em PRs de fork por padrão — não execute código de fork com eles.
