# AUR-560: documentation site (MkDocs Material, container, GitHub Pages)

## Design

- `mkdocs.yml` (root): `docs_dir: docs`, Material theme in pt-BR,
  `navigation.tabs`, `navigation.indexes`, `navigation.top`, `search.suggest`,
  `search.highlight`, `content.code.copy`, plugin `search` with `lang: [pt]`
  (static index, works offline), `strict: true` and link/anchor validation at
  `warn` level so `--strict` fails on a broken link, a page missing from the
  nav or a missing anchor. The `nav` is explicit and grouped by capability:
  Inicio, Comecando, Referencia, Guia corporativo, Qualidade e benchmark and
  Specs. There is no extra plugin, so the image alone builds the site.
- Home page is `docs/index.md`: product overview with one section per
  capability, each linking its reference anchor in `configuration.md` and
  naming its tutorial. A tutorial that does not exist yet is cited as
  `em breve (AUR-56x, `tutorials/<name>.md`)` without a link, so `--strict`
  stays green; AC-004 requires the link as soon as the file exists.
- `docs/README.md` stays the repository entry point. MkDocs drops README.md
  when index.md exists (and the specs link `../README.md`), so
  `scripts/docs/hooks.py` re-adds it as its own page at `/README/`
  (`exclude_docs` lists `/README.md` only to silence the conflict warning).
  `docs/site/` (the older hand-written interactive guide, published by
  `pages.yml`) is excluded except `workflow.yml`, which `getting-started.md`
  links.
- `scripts/docs/build.sh` runs `docker run ... <image@digest> build --strict`;
  `scripts/docs/serve.sh` serves locally. Both read the single line of
  `scripts/docs/image.lock`, which the workflow reaches by calling
  `build.sh`. The `Specs` section (and `Tutoriais` when `docs/tutorials` exists) is not in
  `mkdocs.yml`: `scripts/docs/hooks.py` `on_config` injects it before page
  validation (`specs/README.md`, then `specs/AUR-*.md` in natural order; for
  tutorials `tutorials/README.md`, then `tutorials/*.md`). Nothing to maintain
  by hand; AC-002 reimplements the rule in bash and fails on any orphan page.
- `.github/workflows/docs.yml`: push to `main` (paths `docs/**`, `mkdocs.yml`,
  `scripts/docs/**`, the workflow) and `workflow_dispatch`. Job `build` runs
  `scripts/docs/build.sh` (same image, `--strict`) and uploads `site/`; job
  `deploy` (`needs: build`, environment `github-pages`) is the only one with
  `pages: write` and `id-token: write`.

## Adding tutorials (AUR-561..564)

Each tutorial card creates `docs/tutorials/<name>.md` (and optionally
`docs/tutorials/README.md` as the section index); the hook adds the `Tutoriais`
tab by itself, no `mkdocs.yml` edit. Then replace the
`em breve (AUR-56x, ...)` text in `docs/index.md` by a link to the file.
AC-002 fails on a tutorial that is not in the nav and AC-004 fails on a tutorial
that exists but is not linked from the index. `docs/tutorials` does not exist yet,
so the `Tutoriais` tab does not appear yet.

## Legacy Pages workflow removed

`.github/workflows/pages.yml` is deleted: two workflows deploying to the same
`github-pages` environment overwrite each other, so `docs.yml` is the only
publisher. The hand-written guide in `docs/site/` stays in the repository as an
archive (its `workflow.yml` is still served by the site, linked from
`getting-started.md`); it is no longer published on its own. AC-003 requires
exactly one workflow using `actions/deploy-pages`.

Outside this card's paths: `docs/qa.md` line 19 still says publication uses
`pages.yml`; it needs a one-line fix by whoever owns that page.
