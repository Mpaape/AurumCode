# AUR-578: the review prompt is a template with budgeted slots, sent as messages

## Measurement (before the change, base e6b708fe)

- `internal/prompt/templates/review.md` received `{{.Metrics}}`/`{{.CIContext}}`
  while `buildUserContent` wrote `## Change Summary`, `## Existing CI Context`
  and `## Code Changes` in Go; `## PR history`, `## Codebase context`,
  `## Review memory` (builder.go), `## Review Coverage` (coverage.go) and
  `## Repository context` (config/provider.go) were Go string literals.
- `config.contextInjectingProvider` appended the context block after the
  budgeted prompt (`prompt+"\n\n"+block`), outside `TrimToFit`/`fixedOverhead`,
  and its type assertion hid optional provider interfaces.
- `Reviewer.GenerateReviewWithContext` (177 lines) sent `System+"\n\n"+User` as
  one string through a concrete `*llm.Orchestrator`; `MaxTokens: 0` disabled
  the prompt budget by default.
- `DefaultRuleCatalog` was a hand-written mirror of `review/rules/*.yml`;
  `MaxRuleCatalogTokens = 512` was a Go constant.
- `ReviewIssue` had no origin nor model assessment.
- `formatLanguages` iterated a map: the `## Languages` section of the system
  prompt came out in random order (measured: two runs of the same golden test
  differed at byte 1900). It is now sorted; this is the only byte change to an
  existing section, and it replaces a nondeterministic order with a fixed one.

## What changed

- `internal/prompt/templates/review.md`: the main body is unchanged (system
  message). Named `{{define}}` slots now hold every user-message section:
  `user_header`, `pr_history`, `codebase_context`, `review_memory`,
  `deterministic_evidence` + `evidence_item`, `available_tools` + `tool_item`,
  `coverage`, `repository_context`, `repository_context_slot`.
- `internal/prompt/slots.go`, `sections.go`, `evidence.go`: slot rendering;
  `BuildOptions` gains `Evidence`, `Tools`, `RepositoryContext`. Each is
  counted in `fixedOverhead` (inside the budget). Evidence and tools admit
  whole items under their ceiling and render `- N omitidos pelo orçamento desta
  seção`. Empty input renders nothing (cmd bytes unchanged until AUR-579).
- `internal/prompt/templates/limits.yml` + `limits.go`: default ceilings
  (prompt 120000, rule catalog 512, evidence 4096, tools 1024);
  `MaxRuleCatalogTokens` derives from it; `PromptBuilder.SetSlotLimits`.
- `budgeting.go`: when every segment fits, `TrimToFit` keeps the diff order (a
  ceiling that trims nothing must not reorder hunks; the priority sort put
  `f:10` before `f:2`). `TestTrimToFit_Deterministic` now pins that order.
- `internal/review/rules/catalog.go`: leaf package embedding the rule YAMLs;
  `prompt.DefaultRuleCatalog` derives from it.
- `internal/llm/messages.go`: `MessageCompleter` capability, `FlattenMessages`,
  `SystemUserMessages`, `Unwrapper` and `As[T]` (capability lookup through
  pass-through decorators); `ResolveModelKey` and `AsToolCaller` use `As`.
  `Orchestrator.CompleteMessages` sends messages to a capable provider and the
  flattened text otherwise (estimate always on the flattened text).
  `litellm.Provider.CompleteMessages` sends system and user separately.
- `internal/review`: `Reviewer` depends on `Completer`; `GenerateReviewWithContext`
  is four stages (`preparePrompt`, `complete`, `parse`, `applyGates`, plus
  `annotateResult`), each under 70 lines. `ReviewContext` gains
  `RepositoryContext`, `Evidence`, `Tools`; every evidence/tool field is
  redacted. `Config.PromptTokenBudget` defaults from `limits.yml` and never caps
  the reply. `PromptDigest` and `RequestCacheKey`.
- `internal/review/cache/request_key.go`: `RequestKey(prompt, evidence,
  tool-results digests)` and `DigestOf`.
- `pkg/types`: `ReviewIssue.Origin`, `ReviewIssue.Assessment`
  (`EvidenceAssessment`, statuses `confirmed|disputed|needs_context`). The
  parser clears a model's `origin` and drops an assessment with an unknown
  status or no evidence id; the reviewer redacts the assessment.
- `internal/config/provider.go`: the block is rendered by
  `prompt.RenderRepositoryContext` (same bytes, title in the template).
  `wrap.go`: `contextInjectingProvider` is documented as the compatibility path
  and deliberately does not implement `Unwrapper`.
- Dead code removed: `BuildReviewPrompt`, `buildReviewPromptFallback`
  (`iso_scores` fallback), `TruncatePrompt`, `formatDiffContent` and their
  tests (`builder_test.go`). Zero production callers (grep over cmd, internal,
  tests).

## For AUR-579 (cmd/aurumcode, not in this card's paths)

1. Replace `config.WrapProviderWithWarnings(...)` by
   `config.BuildContextBlockWithWarnings(...)` and pass the block as
   `review.ReviewContext.RepositoryContext`; send through the unwrapped
   provider. `TestRepositoryContextSlotMatchesLegacyDecoratorBytes` proves the
   bytes a single-string provider receives are identical.
2. Replace the positional `reviewContextCacheKey` (review_cache.go:149,
   review_pr_gate.go:47) by `Reviewer.RequestCacheKey(diff, ctx, toolResults)`
   / `cache.RequestKey`.
3. `profileProvider` (profiles.go) and `fixedModelProvider` (cost.go): a
   pass-through decorator implements `llm.Unwrapper`; one that changes the
   request implements the capability it changes explicitly.
4. Wire deterministic evidence (SAST, security pass) into
   `ReviewContext.Evidence`, setting `ReviewIssue.Origin` for engine findings.
5. The response-format text says "Use exactly the fields shown below" while
   the evidence slot asks for `assessment`; reconcile both when evidence is
   wired in. An issue that only carries a `disputed`/`needs_context`
   assessment does not survive the precision and rule gates (and its discard
   withholds the summary); `evidence_id` is not yet checked against the
   evidence offered.

## Behavior visible to cmd (deliberate, required by the card)

- The default prompt ceiling (120000 tokens, `limits.yml`) is now active: a
  diff beyond it is trimmed by whole hunks and declared in the coverage
  section; fixed content beyond it is a loud error instead of a sent prompt.
- `FixedContentDigest` moved (new slot sentinels): existing review caches are
  invalidated once.
- `## Languages` is rendered sorted (it was random).
- An unwrapped litellm provider now receives a separate system message; when
  cmd wraps it (repository context, profiles, fixed model) it still receives
  the flattened text, until AUR-579.
