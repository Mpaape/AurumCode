# AUR-480 - Fonte opcional de contexto falha com aviso sem apagar o review

## Medido antes

O comportamento ja existe no codigo e nao foi alterado. Este card entrega apenas a caracterizacao.

- `internal/config/provider.go` `callProviderBounded`: cada provider roda sob `ProviderTimeout` (10s) e `MaxProviderContributionBytes`; trava, erro e estouro de prazo viram erro nomeado (`context provider "<nome>" ...`).
- `BuildContextBlockWithWarnings`: falha de provider vira `ProviderWarning{Provider, Reason}`, ambos passam por `filter.Redact`, o provider e omitido e os demais continuam. So o estouro de tamanho (`contributionLimitError`) continua erro duro.
- `internal/config/provider_files.go`: `ConfiguredProviders` trata `.aurumcode/prompt.md` ausente como opcional (`""`, sem aviso); toda fonte escrita explicitamente (`ContextFile.Optional == false`) devolve erro quando ausente, e esse erro aparece como aviso nomeado.
- `Parse`/`Load`: YAML malformado, chave desconhecida (`decodeStrict`) e path de contexto fora do repo continuam erro; arquivo escrito e invalido nunca vira config vazia.
- O texto do provider so entra no prompt (`prompt.RenderRepositoryContext`); nenhuma API de decisao (gate, regras, severidade, redacao) recebe texto de provider.
- Teste existente: `TestAUR480ProviderFailureWarnsAndContinues` (`provider_pending_test.go`).

## O que mudou

- `tests/acceptance/AUR-480.sh`: copia `cmd internal pkg go.mod go.sum` inteiros para uma raiz temporaria, grava ali `internal/config/aur480_acceptance_test.go` e roda `go test` do pacote. O repositorio nao e tocado.
- `docs/specs/AUR-480.md`: este documento. Nenhum arquivo de `cmd/`, `internal/` ou `pkg/` foi editado.
