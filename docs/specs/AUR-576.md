# AUR-576: one review session serves --base and --pr

## Measurement (before the change, base 1569d875)

- `baseReview` (review_base.go, ~45 fields) and `prReview` (review_pr.go, ~55
  fields) held the same data under different names (`repoCfg`/`cfg`,
  `codebaseContextText`/`codebaseText`, `contextBlockDigest`/`contextBlockDig`,
  `ruleCatalogDigest`/`ruleCatalogDig`, `rawIssues`/`rawIssuesSnapshot`).
- Two phase lists (`runReview`: resolveInputs, analyze, decideGate, publish;
  `runPRReview`: validate, resolveInputs, analyze, runGate, publish), each
  with its own analyze sub-list.
- Two `inconclusiveReason` (main.go and review_pr_gate.go): base
  `provider_failure`/`quality_skipped`, PR the constant and
  `model_parse_failure`; the rest of the ranking was copied.
- Two exit ladders: base (quality failed > gate > artifacts > fail-on) and PR
  (comment failures > `--exigir-qualidade` degraded > status failure > gate >
  artifacts > fail-on > `--check` status).
- `runSAST` copied (only PR had `sastReasonUnverifiedCheckout`);
  `writeComplianceArtifacts` assembled twice, with `run.IssuesForGate()` on
  base and `result.Issues` on PR.
- Security findings: base kept them in `run.Extra` and applied the rule config
  separately, and its raw verdict snapshot did NOT contain them; PR merged them
  into `result.Issues` before the snapshot.
- `os.Getenv("GITHUB_SHA")` read in both gate phases (and `AURUMCODE_BASE_SHA`,
  `GITHUB_REPOSITORY`, `LLM_MODEL`, `AURUMCODE_OUTPUT_FILE`,
  `AURUMCODE_PR_PERMISSION_MODE` across the phases).
- Package-variable seams: `gatePipelineObserver`, `evaluateGate`,
  `newGatePipeline`, `diffContentDigest` (review_gate.go),
  `resolveWithFilesHook` (verified_checkout.go), `newCacheDigestBuilder`
  (review_cache.go); `Now: time.Now` fixed in both gate phases.
- `runPRReview` took 9 positional parameters.

## What changed

- `internal/gate/reason.go`: `ModelOutcome` (reviewed, skipped, provider
  failed, parse failed), typed `Reason` constants and `RankReason`, the one
  ranking (provider failure > skipped > model parse failure > degraded parse >
  SAST reason > partial coverage). Tokens are unchanged. `NotReviewedRules`
  maps an outcome to "not reviewed" (never, when quality is required, always);
  the requirement is a typed `QualityRequirement` (optional, required).
- `internal/gate/exit.go`: `ExitPolicy(ExitInputs) ExitDecision`, one ladder of
  rungs with typed inputs and a named cause; `ExitClean/ExitBehavioral/
  ExitFindings`. cmd's `exitFindings`, `exitQualityNotReviewed`,
  `exitArtifactNotWritten` now alias these values.
- `internal/review/session`: `Phase`, `Order` (resolve, model, evidence, gate,
  publish), `Run`, and `Source` data: `LocalDiff` and `PullRequest` with their
  `NotReviewedRules`, where the security findings live and the notice printed
  when "not reviewed" decides. AUR-579 changes the model/evidence order by
  editing `Order` only.
- `cmd/aurumcode/review_session.go`: `reviewState` (the shared fields, one
  name each), `reviewDeps` (clock, Semgrep runner, gate observer, codebase
  resolver, prompt digest builder, environment snapshot; zero fields take the
  production default), `reviewEnv` (read once by `readReviewEnv`), `reviewIO`.
- `cmd/aurumcode/review_evidence.go`: the shared evidence steps:
  `runSecurityPass`, `joinSecurityFindings` (the one place that decides where
  security findings live), `snapshotAndApplyRules` (snapshot = issues + the
  kept-apart security findings, on both sources), `runSAST(root, blocked)`,
  `findingsAtThreshold`, `writeArtifacts` (one assembly from the gate run:
  `run.IssuesForGate()`).
- `cmd/aurumcode/review_gate.go`: the shared gate phase (`runGate`,
  `gatePipelineInputs`, `executeGate` with the injected observer),
  `inconclusiveReason` over `gate.RankReason`, `decideExit` over
  `gate.ExitPolicy`. The seams became plain calls or injected dependencies.
- `baseReview` and `prReview` embed `reviewState`, implement
  `session.Phases.Step`, and keep only their own fields. `review_base_gate.go`
  and `review_pr_gate.go` are gone; `failOnExit`, `exitCode` and the two
  `writeArtifacts` are gone.
- `runPRReview(reviewIO, prReviewOptions)`: the PR number, repository,
  `--publicar`, `--na-linha` and `--check` joined the options struct.
  `runReviewWith(reviewIO, args)` is the entry that takes dependencies.
- Tests that substituted package seams inject them through `reviewDeps`
  (aur524, aur536, aur543, review_gate_test via `runReviewWith`,
  `runPR499With`, `runAUR536ReviewWith`). No `t.Setenv("PATH")` was added
  (6 before, 6 after).

## Per-source mapping (data, not code)

| Outcome | `--base` | `--pr` |
| --- | --- | --- |
| provider failed | always not reviewed | not reviewed only with `--exigir-qualidade` |
| parse failed | always not reviewed (not reachable today: base classifies every model error as provider failed) | not reviewed only with `--exigir-qualidade` |
| skipped | gate decides; `--exigir-qualidade` classifies it as provider failed (AUR-458) | not reachable |

Unifying these divergences is a product decision for a later card; no e2e
exit code changes here.

## Exit precedence (one ladder)

comment publish failure (1) > not reviewed (1) > status publish failure (1) >
gate breach (3) > gate block (1) > artifact not written (1) > `--fail-on` (3)
> `--check` status code. It is the union of the two old ladders: base had no
publication rungs, and on every input both old ladders already agreed with it,
so no fail-closed choice changed an exit. The notice printed when "not
reviewed" decides is source data (only `--pr` prints the
`--exigir-qualidade` line, as before).

## Snapshot change (AC-003)

The `--base` raw verdict snapshot now includes the security pass's findings,
as `--pr`'s always did. The verdict-reuse key is unchanged; a verdict stored
by an older binary without security findings can only be re-evaluated with
fewer findings, and the gate's own security contributor still counts the
current run's security findings.

## How AC-002 is proven

- `TestAUR576SameInputsSameExitThroughTheSession` (cmd/aurumcode): for each row
  it builds a `reviewState` per source with the same config, diff, model
  outcome, findings and injected dependencies (fixed clock, a Semgrep runner
  that is not installed, an empty environment), then runs the real evidence
  steps, the real gate pipeline (`runGate`) and the real exit decision
  (`decideExit`), and compares the exit codes and the published
  `policy gate:` lines. Rows: provider failure (block), parse failure
  (block), scanner missing, artifact not written over a `--fail-on` finding,
  a finding above the gate threshold, a finding above `--fail-on`, clean; a
  row whose gate must speak fails if it published no line. Declared
  divergent rows: provider failure under `warn` (`--base` 1, `--pr` 0) and
  provider failure with a breach (`--base` 1, `--pr` 3).
- `TestAUR576SameInputsSameExitOnBothSources` (internal/review/session): the
  same table over `RankReason`, the sources' `NotReviewedRules` and
  `ExitPolicy`.
- `TestExitPolicyPrecedence`, `TestRankReasonOrder` (internal/gate).
- MUT-001 is three edits, each RED: a second exit ladder in the `--base`
  publisher (AC-001's AST test), a reordered shared ladder (the ladder and
  table tests), and a `--base`-only rung putting `--fail-on` above a missing
  artifact in `decideExit` (the behavioral table above).

construction behind the session is left for the card that splits them
(AUR-584).
