# AUR-581: gitleaks is a registered engine

## Measured before (base e1f14ef7)

- gitleaks was pinned in `.board/bootstrap/locks/scanners.yml` (v8.30.1,
  `docker.io/zricethezav/gitleaks@sha256:c00b6bd0...`, rule base
  `gitleaks-default-config-v8.30.1`, `sha256:e163e53b...`) and no code ran it.
- `scanner.Request` carried `Root, Trust, Options, Command`: no commit range,
  so no engine could scan a pull request's history.
- `scanner.Outcome` dropped `Report.Version`.

### The pinned binary, measured on the host (2026-10-03)

`docker run --rm docker.io/zricethezav/gitleaks@sha256:c00b6bd0aeb3071cbcb79009cb16a60dd9e0a7c60e2be9ab65d25e6bc8abbb7f git --help`
and `... version` (`v8.30.1`), then runs over a fixture repository created at
run time (base commit; a commit adding a GitHub token built by concatenation;
a commit removing it; a commit adding the same token with `# gitleaks:allow`):

| Run | Result |
| --- | --- |
| `git --log-opts=<base>..<head>` | 1 leak (`github-pat`, `leak.txt:1`, the intermediate commit); the allowed line is suppressed |
| same + `--ignore-gitleaks-allow` | 2 leaks |
| same + `--redact` | `Secret` = `REDACTED`, `Match` = `REDACTED` |
| `dir` over the final tree | 0 leaks (the token was removed; the allowed line is suppressed) |
| `.gitleaksignore` with the leak's fingerprint at the repository root, cwd = repo / cwd elsewhere / `-i <empty dir>` / both | the leak is ignored in **every** case: gitleaks always reads `<source>/.gitleaksignore`; no flag disables it |
| `.gitleaksignore` in a subdirectory | not read |
| `.gitleaks.toml` at the root allowlisting both files | 0 leaks (the repository replaces the rule base) |
| same + `--config <file with [extend] useDefault = true>` | 2 leaks (explicit config outranks the root file) |
| `--log-opts=deadbeef..<head>` (unknown base) | `ERR [git] fatal: ambiguous argument`, **exit 0, report `[]`, "no leaks found"** |
| `--log-opts=<head>..<head>` | exit 0, `[]` |
| unknown base with the engine's flags (`--no-color` included), stderr through `cat -v` | plain `7:51PM ERR [git] fatal: ambiguous argument ...`, no escape codes; the engine still strips ANSI color before matching `ERR`/`FTL` |

The report's keys: `Author, Commit, Date, Description, Email, EndColumn,
EndLine, Entropy, File, Fingerprint, Match, Message, RuleID, Secret,
StartColumn, StartLine, SymlinkFile, Tags`.

## What changed

- `internal/scanner/scanner.go`: `Request.Range{Base, Head}` (the reviewed
  commit range; `Empty()`); `executor.go`: `Outcome.Version` carries
  `Report.Version`.
- `internal/scanner/gitleaks` (new; `engine.go`, `invocation.go`,
  `report.go`), registered in `internal/scanner/engines`: name and origin
  `gitleaks`, category `secrets`, no options.
  - `gitleaks version` first: a missing binary keeps `exec.ErrNotFound`
    (`secrets_unavailable`); any version but `v8.30.1` is an error.
  - The range is verified before gitleaks sees it, because gitleaks itself
    reads an unknown revision as a clean scan: both ends must be full commit
    ids (so neither can be an option), the repository must not be shallow
    (`git rev-parse --is-shallow-repository`), and both commits must exist
    (`git cat-file -e <id>^{commit}`). An empty range is an error: there is
    no fallback to the final tree.
  - `gitleaks git --log-opts=<base>..<head> --report-format json
    --report-path <tmp>/report.json --exit-code 0 --no-banner --no-color
    --redact --config <tmp>/pinned.toml .`, the temporary directory private
    and removed. `pinned.toml` is `[extend] useDefault = true`: the bundled
    (pinned) rule base, ahead of `GITLEAKS_CONFIG`, `GITLEAKS_CONFIG_TOML`
    and a root `.gitleaks.toml`.
  - A non-zero exit, an `ERR`/`FTL` log line, a missing report, a report that
    is not a JSON array, or an entry without rule, file or line is a failed
    scan (`secrets_execution_error` / `secrets_invalid_output`).
  - The report is decoded into `leak{RuleID, Description, File, StartLine,
    Commit}`: there is no field for `Secret`, `Match`, `Line`, the commit
    `Message`, `Author` or `Email`, so they are discarded by the decoder
    before anything else (gitleaks' own `--redact` is the second line). A
    finding is `gitleaks:<rule>` at `file:line`, severity `error` (gitleaks
    has no severity; the entry's `fail_on`, default `ERROR`, decides), message
    `<rule description> in commit <12 hex> (gitleaks v8.30.1)`.
  - Policy (`TrustPolicy`): `--ignore-gitleaks-allow` and
    `--gitleaks-ignore-path <tmp>`. Because the root `.gitleaksignore` is
    still read (measured above), its presence under policy is the blocking
    finding `gitleaks:ignore-file-present` at `.gitleaksignore:1`: the policy
    owner has to clear it. Residue: findings the file hides are not reported
    individually; the scan as a whole cannot pass while it exists.
  - `Report.Version` = `gitleaks v8.30.1 rulebase
    gitleaks-default-config-v8.30.1 sha256:e163e53b...` (`Identity`).
- `.github/workflows/review.yml`: step `Install pinned gitleaks` reads image
  and version from the lock in the tool checkout, refuses an image not pinned
  by digest, pulls by digest (fails if the bytes differ), copies
  `/usr/bin/gitleaks` (static) into `aurumcode-review` and fails unless
  `gitleaks version` equals the lock's version; the pull request checkout uses
  `fetch-depth: 0` (a shallow clone would cut the range); the review container
  gets `GIT_CONFIG_COUNT/KEY_0/VALUE_0` = `safe.directory=/github/workspace`
  (git in the container is another user than the checkout's owner).
- Docs: `docs/configuration.md` (engine section, `secrets` source),
  `docs/gate-corporativo.md`.

## Observable change

Registering a second category extends the accepted-source list of
`gate.sources`/`gate.triage` errors: `gate.sources: unknown source "supply"
(accepted: skills, analysis, sast, secrets)` (AUR-577's spec said the text
"keeps listing skills, analysis, sast"; it now also lists `secrets`). The gate
tutorial's `expected/falha-fonte-invalida.txt` and the block in
`docs/tutorials/gate.md` were updated to the new text. No other output
changed.

No lock field was added: `scanners.yml` already holds every value used
(`secrets_scanner_image`, `secrets_scanner_version`, `secrets_rulebase_id`,
`secrets_rulebase_sha256`); `TestGitleaksIdentityMatchesScannersLock` ties the
engine's constants to them.

## Not delivered (outside this card's paths)

1. **Range wiring in `cmd/aurumcode`** (card `paths` exclude `cmd`, and the
   parallel AUR-580 owns it). Until it lands every enabled `gitleaks` entry is
   `secrets_execution_error` (fail closed). The change:
   - `scanner_pass.go`: `runScanners(root string, r scanner.Range, blocked
     string)` and `scanner.Request{Root: root, Trust: trust, Options:
     entry.Options, Range: r}` (AUR-577's MUT-001 anchor
     `out := s.deps.scanners.Scan(s.ctx, engine, scanner.Request{` is kept);
   - `review_pr_analysis.go`: `scanner.Range{Base: p.env().baseSHA, Head:
     p.env().githubSHA}`;
   - `review_base_analysis.go`: the `--base` ref and `HEAD` resolved to full
     ids (`git rev-parse --verify <ref>^{commit}`) before the call.
2. **Result digest**: `Outcome.Version` is exposed; the review's request key
   (`cmd/aurumcode/review_weighing.go`) must fold each scan's `Version` into
   the evidence digest. Today the evidence items carry rule, file and line,
   not the engine version.
3. **Product image** (`Dockerfile`, outside `paths`): the tutorials build
   from it, so the secrets tutorial needs gitleaks in it. The workflow
   overlay above is the same recipe (`COPY --from=<lock image>`).
4. **Tutorial `docs/tutorials/segredos.md` + `demo/tutoriais/segredos`**:
   three of its four cases need item 1 and item 3; not written. AC-004's
   tutorial half fails with `AUR-581/AC-004/tutorial-missing`.
5. The optional docker integration test was not written: Go runs only in the
   shared container, which has no docker; the pinned binary's behavior is the
   host transcript above.
