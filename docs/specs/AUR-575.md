# AUR-575: o gate falha fechado por construção

## Medido antes (auditoria de 2026-10-03, base `e6b708fe`)

1. `config.Parse` validava `gate`, exceções, `analysis_data`, `ssor_dtrack` e
   `supply_chain`, mas nunca `quality_gates.sast` (`SastConfig.Validate` só era
   chamado pelos testes): `engine: gitleaks` rodava o Semgrep calado e um
   `rule_packs` com cara de flag passava.
2. O `.aurumcode/config.yml` do repositório era lido com `yaml.Unmarshal`
   leniente; só a política central fazia um segundo decode com
   `KnownFields(true)`. `gate: {fial_on: [error]}` não declarava gate e aprovava.
3. `gate.inconclusive` ausente valia `""`, tratado como `warn` em todo lugar:
   SAST habilitado com Semgrep ausente saía 0 com status `success` (alerta).
4. Cada fonte decidia sozinha o modo: Dependency-Track e `analysis_data`
   calculavam `Fail` pelo modo, o SAST só marcava `Inconclusive`, o pipeline
   tratava o erro de contribuidor à parte, e a falha de artefato também.
5. `sources.go` (loop determinístico: catálogo embutido e passe de segurança) e
   `sast.go` descartavam com `continue` uma severidade que `SeverityRankOf` não
   reconhecia.

## O que mudou

- `internal/config/decode.go`: `decodeStrict` (`KnownFields(true)`, documento
  vazio = configuração zero) é o decoder de `Parse`; o decode extra da política
  em `central.go` saiu (a mensagem é a mesma: `parsing <arquivo>: yaml: unmarshal
  errors: line N: field X not found in type ...`).
- `Parse` chama `QualityGates.Sast.Validate()`.
- `internal/config/gate.go`: `resolveInconclusive(fallback)` normaliza o valor;
  `GateConfig.InconclusiveMode()` resolve ausente para `block` quando o gate é
  declarado. `internal/config/inconclusive.go`: `Config.InconclusiveMode()`
  resolve ausente para `block` quando há gate **ou** scanner habilitado (SAST,
  Dependency-Track, `analysis_data`); `warn` só escrito.
- `internal/gate/pipeline.go`: `ApplyInconclusiveMode` é o único ponto que
  transforma `Inconclusive` em `Fail` (modo `block`, ou modo ilegível); o
  pipeline aplica após cada contribuidor, e a falha de artefato pós-pipeline
  reaplica a mesma função. Dependency-Track, `analysis_data`, artefatos, erro de
  contribuidor e `EvaluateGate` só marcam `Inconclusive` (`EvaluateGate` ainda lê
  o modo para não graduar um run bloqueado). `aurumcode sbom` usa
  `ApplyInconclusiveModeValue` com o modo do gate.
- `internal/gate/policy.go`: `GateRankOf` conta severidade desconhecida como
  `error`; usado em `sast.go` e `sources.go`.
- Testes que afirmavam o padrão antigo (`warn` implícito) foram atualizados para
  o novo contrato; `analysisdata_test.go` usava a chave inexistente `language`
  na raiz (o decode estrito revelou; a chave real é `review.language`);
  `aur572_test.go` escreve `inconclusive: warn` porque testa a linha final do
  relatório, não o modo.
- Tutorial do gate: política `politica-sast-padrao` (SAST habilitado, sem
  `gate`), caso com `PATH=/sem-semgrep` que sai 1; `expected/` e `out/`
  regravados com a imagem do produto; docs `configuration.md`,
  `gate-corporativo.md` e `tutorials/gate.md` atualizados.
