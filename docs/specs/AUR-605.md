# AUR-605 — Provedor reserva (fallback)

## Medido

- `llm.Orchestrator` já percorria uma cadeia de provedores, mas todos os
  chamadores (`review`, perfis, qualidade da base, dependências, changelog)
  passavam a lista de reservas vazia (`NewOrchestrator(p, nil, ...)`).
- Não havia variável, input nem secret para declarar uma reserva. Com o
  provedor fora do ar a revisão falhava fechada, sem plano B.
- O limite de tempo do orquestrador era um só por requisição: uma cadeia
  cujo primeiro provedor esgotasse o limite nunca ouviria a reserva.

## O que mudou

| arquivo | responsabilidade |
|---|---|
| `internal/llm/fallback.go` | `NewFallback` (principal sozinho quando não há reserva), `Fallback` e `ToolFallback` (só membros que chamam ferramentas recebem rodada com ferramentas); `FallbackNotice` anuncia cada troca; erro final nomeia cada membro e responde a `errors.Is(ErrAllProvidersFailed)`; `TimeoutScaler`/`callTimeout`: um limite por membro. |
| `internal/llm/orchestrator.go`, `orchestrator_tools.go` | Limite de tempo por `callTimeout(provider)`; erro de cadeia devolvido sem embrulho duplicado. |
| `internal/llm/provider/profiles/fallback.go` | `FallbacksFromEnv`: slots `LLM_FALLBACK_1..5_*` resolvidos pelo catálogo, URL e chave do slot no lugar das do principal, inclusive as variáveis nativas de chave do perfil, modelo próprio; slot pela metade é erro com as variáveis do slot. |
| `internal/llm/provider/profiles/resolve.go` | `catalogFromEnv` compartilhado entre principal e reservas. |
| `cmd/aurumcode/provider_fallback.go` | `withFallbacks` monta a cadeia atrás do principal; `slotProvider` nomeia a reserva pelo slot; aviso no stderr redigido. |
| `cmd/aurumcode/review_cache.go`, `review_base_quality.go` | Chave do cache acha a URL atrás da cadeia (`llm.As`); revisão respondida por reserva (`FellBack`) não é gravada. |
| `cmd/aurumcode/main.go`, `profiles.go` | `providerFromEnv` usa `withFallbacks`; o perfil de revisão repassa o limite da cadeia. |
| `.github/workflows/review.yml` | Inputs `fallback_{1,2}_provider`/`_model`, secrets opcionais `LLM_FALLBACK_{1,2}_API_KEY`/`_BASE_URL`, nos jobs de revisão e de dependências. |
| `docs/provedores.md`, `docs/tutorials/provedores.md`, `demo/tutoriais/provedores` | Seção "Provedor reserva" e quatro casos executáveis com o provedor falso (rota `fora-do-ar` responde 503). |
