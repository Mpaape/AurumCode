## Decisões

- **O produto, não um simulacro.** Cada caso roda `/app/aurumcode` da imagem
  construída do `Dockerfile` da raiz, sem rede, com o provedor falso. A fase de
  PR é conferência do workflow, não revisão de PR (ver "Limites").
- **Blocos literais.** O texto marca `<!-- arquivo: PATH -->` antes do bloco; o
  aceite compara byte a byte. Saídas esperadas marcam `<!-- saida: caso -->`;
  cada linha do bloco tem de existir em `out/<caso>.log` (AC-002).
- **Saída copiada, não escrita.** `expected/` guarda só linhas que provam o caso;
  o texto só mostra linhas presentes no `out/`.
- **`.gitignore`.** O `.gitignore` da raiz ignora `*.log`; `demo/tutoriais/.gitignore`
  reabre `out/` para os tutoriais (o `out/` é evidência versionada).
- **Texto de rede omitido, declaradamente.** Só em `politica-central/analysis-data`,
  o detalhe do erro de rede (varia por ambiente) é trocado por
  `<detalhe de rede omitido do registro>` por `TUT_SED`, documentado no `run.sh`.

## Achados sobre o produto (honestidade do tutorial)

1. **Seleção por linguagem e apelidos não estão ligados ao `review`.**
   `.aurumcode/skills/<nome>/SKILL.md` com `languages: [...]`
   (`internal/context/skills`, AUR-468/AUR-559) é biblioteca: só testes
   (`tests/unit/AUR-468.go`, `internal/context/skills/aur559_test.go`) chamam
   `skills.Providers`. A CLI usa `review.context.skills` (lista explícita) e
   `.aurumcode/instructions/*.md` com `applyTo` (escopo por caminho). O tutorial
   de skills prova o negativo (`selecao-por-linguagem`) e usa o escopo por
   caminho como seletor funcional. O bloco `### Skill selection warnings`
   (apelido desconhecido) só existe na biblioteca; teste que o cobre, rodado no
   go-shared nesta execução: `TestAUR559AliasResolvesAndUnknownIsDeclared` PASS.
2. **Skill ausente no repositório é aviso, não erro.** `continuing without that
   context`, e achados que citam os ids dessa skill são descartados; o parecer
   pode sair `Approve`. Na política central é erro de carga (exit 1). O
   tutorial registra isso.
3. **`fix` imprime um patch sem contexto** (`@@ -6,1 +6,1 @@`): `git apply`
   exige `--unidiff-zero` (o `docs/getting-started.md` mostra `git apply` sem
   a flag).
4. **Cobertura parcial sem gate sai 0** com veredito `Comment`; só com
   `gate.inconclusive: block` reprova (exit 1, `partial_coverage`).
5. `analysis_data` declarado numa política faz o review consultar o GitHub: sem
   rede é inconclusivo (`analysis_data_unavailable`).

## Limites

- Não há runner do GitHub nem servidor GitHub reutilizável fora dos testes Go
  (os falsos de `cmd/aurumcode/*_test.go` são `httptest` em Go); então o caso
  "revisão de PR" prova só a coerência do workflow do chamador com
  `.github/workflows/review.yml` (inputs, secrets, permissões, `policy_*`). O
  `review --pr` não é executado.
- `AURUMCODE_PROMPT_CAPTURE` (observação do prompt) é variável interna de
  observação, usada só para mostrar o que chegou ao modelo.
- `AURUMCODE_CACHE_DIR` não é definido: o aviso `gate verdict reuse
  unavailable` aparece nos logs e é esperado.
