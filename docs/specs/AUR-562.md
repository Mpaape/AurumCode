# AUR-562: tutoriais executáveis do gate, exceções, auditoria/SARIF e reaproveitamento

## O que entrega

- Quatro tutoriais em `docs/tutorials/` (`gate.md`, `excecoes.md`,
  `auditoria-sarif.md`, `reaproveitamento.md`), indexados em
  `docs/tutorials/README.md` e linkados da página inicial (`docs/index.md`); o nav
  vem do hook do site (aba Tutoriais).
- Quatro demonstrações em `demo/tutoriais/<tutorial>/` no framework do AUR-561
  (`run.sh` com uma fase por caso, `expected/`, `out/` da execução real).
- Uma extensão do framework, em arquivos **novos** (o `tutorial.sh` não foi
  editado): `demo/tutoriais/_lib/github-falso.py` e `_lib/pr.sh`. O primeiro é um
  GitHub falso e local (127.0.0.1) que só serve o que `review --pr` consulta e
  registra o que o produto publica; o segundo expõe `tut_pr_servidor`, `aurum_pr`
  (container em `--network host`, só para alcançar o loopback do host) e
  `tut_pr_log`. Serve para provar o **texto publicado** do status
  `aurumcode/policy-gate`; não é um runner nem o GitHub.
- `tests/acceptance/AUR-562.sh`: `all`, `AC-001`..`AC-004`, `AC-002-MUT-001`;
  seletor desconhecido sai 64.

## Decisões

- O SAST usa o **Semgrep real** da imagem com uma regra local (sem rede); a falha
  do SAST é simulada por um `semgrep` falso na frente do `PATH` (`gate/fakebin/`),
  declarado no `run.sh` e no tutorial.
- Conclusões do script são frases `RESULTADO:` afirmadas por `expect_rc`; o que não
  tem caso executado leva a marca "não demonstrado aqui" no texto.

## Não demonstrado aqui (declarado)

- Artefato de análise vencido (`analysis_data_stale`) e digest divergente: exigem um
  servidor de releases; só `analysis_data_unavailable` (sem rede) é executado.
- SBOM na auditoria: exige Trivy e rede.
- Upload ao Code Scanning (`upload-sarif`) e a proteção de branch: configuração do
  GitHub; a demo confere o workflow do chamador contra o `review.yml` real.
- Compartilhamento da mesma chave de veredito entre `--base` e `--pr` (ver achado 4).
- `--pr` roda contra o GitHub **falso**: prova o que o produto publica, não o
  comportamento do GitHub.

## Achados sobre o produto (o que o tutorial mediu)

1. **A origem na linha de gate não é uniforme.** A auditoria e o SARIF trazem o
   `origin` tipado (`skills`, `analysis`, `sast`), mas a linha impressa diz `origem
   analysis` só para a análise; para o SAST diz `origem policy` (de onde veio a
   configuração) e para a skill não diz nada. `docs/configuration.md` promete a
   origem "nas linhas de gate". Caso `gate/fontes`.
2. **Falha ao gravar a auditoria não reprova.** `--auditoria` num diretório
   inexistente avisa em stderr e a saída segue 0 numa revisão limpa; um pipeline de
   compliance precisa conferir o arquivo. Caso `auditoria-sarif/falha-caminho-invalido`.
3. **A mensagem do gate é redigida de forma diferente do relatório.** A linha de
   gate mostra `[REDACTED] secret or credential assigned inline` onde o relatório
   mostra `Hardcoded secret or credential assigned inline`.
4. **`--base` e `--pr` gravaram chaves de veredito diferentes** neste experimento
   (mesmo SHA, política, modelo e identidade do repositório; diff do GitHub falso).
   Não é possível afirmar que seja defeito do produto: o diff do servidor falso pode
   diferir do real. Caso `reaproveitamento/veredito-base-e-pr`.
5. **O cache por arquivo atravessa uma mudança de política** (a resposta do modelo
   não mudou); só o veredito é por política. Documentado nos tutoriais.
6. Observado em experimento exploratório, **não versionado**: sem provedor, com
   `--seguranca` e `inconclusive: warn`, um achado `[error]` do passe de segurança
   (`security/hardcoded-secret`) apareceu no relatório e a saída foi 0 com
   `fail_on: [high]`. Precisa de um caso próprio antes de ser afirmado.

## Execução real

Execução real, em container, com a imagem `aurum-tutoriais:local` construída do
`Dockerfile` do worktree, sem rede (exceto o loopback do GitHub falso no caso
`gate/status-pr` e em `reaproveitamento/veredito-base-e-pr`) e com o provedor
falso. Comandos: `bash demo/tutoriais/<t>/run.sh all` (os quatro terminaram com
exit 0) e `run.sh --check`. A saída completa de cada caso é
`demo/tutoriais/<t>/out/<caso>.log`.
