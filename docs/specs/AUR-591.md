# AUR-591: o Aurum revisa o Aurum por PR, com configuração mínima e skills de convenção

## Medido antes (base b29ca936)

- `.aurumcode/config.yml` só declarava `review.language: pt-BR` e
  `ignore: tests/**`: sem `gate`, sem scanners, sem deliberação, sem skills.
  `.aurumcode/skills/` não existia.
- `.github/workflows/code-review.yml` chama `./.github/workflows/review.yml`
  (check obrigatório de `main`: `review / Review pull request`). Os secrets
  `LLM_API_KEY`/`LLM_BASE_URL` existem no repositório; a última execução
  (2026-10-02, PR do dependabot, sem secrets) falhou no passo "Check provider
  configuration" sem publicar `aurumcode/policy-gate` com o motivo.
- Os cards eram integrados por merge local e push direto em `main`.
- Medido com o binário da base (container `go-shared`): uma skill em
  `.aurumcode/skills/<nome>/SKILL.md` **chega ao prompt**, mas um achado que
  a cita (`tamanho#...` ou `SKILL#...`) é descartado (`1 citing an unknown
  rule_id`). Regras citáveis vêm só de `review.context.skills`, com id
  `<nome-do-arquivo>#<slug>`; listado, o `SKILL.md` gera `SKILL#<slug>` e o
  achado reprova o gate (rc 3).
- Medido na imagem do produto construída deste worktree
  (`aurumcode-review:aur591`, a mesma receita do `review.yml`), primeiro num
  repositório de um arquivo e depois **sobre a árvore real** (clone do
  worktree, fixture de modelo sem achados, `review --base`):
  - `govet` ligado: `lint_unavailable` em toda revisão (a imagem não traz
    `go`) → inconclusivo → bloqueio.
  - `semgrep` (árvore inteira, `p/security-audit` + `p/owasp-top-ten`):
    `sast_invalid_output`, porque o relatório traz 13 erros de parse nível
    `warn` (scripts bash, `action.yml`, locks YAML), e 9 achados `ERROR` em
    arquivos que a PR não tocou (Dockerfiles, `demo/bad-code.go`,
    `secrets: inherit` do `code-review.yml`). Ligado, bloquearia toda PR.
  - `gitleaks` (intervalo da PR): sem achados nem inconclusivo.
  - Num intervalo que toca `docs/assets/capturas/capturas.json`: achados
    `analysis/hardcoded-secret` (as capturas reproduzem os canários dos
    tutoriais) → `docs/assets/capturas/**` entrou no `ignore`.
  - **Cobertura parcial**: um arquivo oculto por `ignore` (ex.:
    `tests/acceptance/AUR-591.sh`) ou um binário (PNG das capturas, mesmo sob
    caminho ignorado) conta como cobertura parcial (`partial_coverage`), que
    com `inconclusive: block` reprova. O gate imprime só o motivo de maior
    rank: na primeira medição ele estava escondido atrás do `sast_*`.

## O que mudou

- `.aurumcode/config.yml` (20 linhas úteis, comentado, depois do merge do
  AUR-593): `review.language`, `ignore` com `tests/**` e
  `docs/assets/capturas/**`, `gate: {fail_on: [error], inconclusive: block}`,
  `quality_gates.scanners` com `gitleaks` (`required: true`), `semgrep` e
  `govet` (`fail_on: warning`), e `deliberation` ligada com `max_rounds: 3`,
  `max_cost_tokens: 60000`, `per_tool_timeout_seconds: 120`. Nenhuma skill
  listada em `review.context.skills`: as de diretório já são citáveis.
- `.aurumcode/skills/<nome>/SKILL.md` (formato do AUR-565, `paths` entre
  aspas), uma por convenção, cada regra com id próprio, exemplo de violação e
  de correção:
  - `arquitetura`: `ARQ-001` lógica em `internal/`, `cmd/` só monta (warning).
  - `tamanho`: `TAM-001` função ≤150 linhas, `TAM-002` arquivo ≤400 (error).
  - `sem-numero-de-card`: `CARD-001` sem id de card em código/doc de pacote (warning).
  - `repo-publico`: `PUB-001` sem empresa/domínio interno/repo privado,
    `PUB-002` sem segredo (error).
  - `sem-bool-exportado`: `BOOL-001` sem parâmetro `bool` em função exportada (error).
  - `gate-fail-closed`: `GATE-001` erro/ausência/dúvida nunca aprova (error).
  Ids citáveis `<dir>#<slug>`: `arquitetura#arq-001-logica-fica-em-internal-cmd-so-monta`,
  `tamanho#tam-001-funcao-com-no-maximo-150-linhas`, etc. Cada skill só entra
  no prompt quando um arquivo alterado casa com o seu `paths`. As regras
  subjetivas (`ARQ-001`, `CARD-001`) ficam em `warning` (publicam sem
  reprovar); as objetivas têm `severity: error` como piso.
- `.github/workflows/code-review.yml`: comentário explicando que, num
  `pull_request`, `job.workflow_sha` do `review.yml` local é o commit de merge
  da PR (o binário que revisa é o da PR); novo job paralelo `provider`
  (sem `needs`, porque check pulado conta como aprovado) que, sem
  `LLM_API_KEY`/`LLM_BASE_URL`, publica `aurumcode/policy-gate` = `failure`
  com o motivo e sai 1; com os secrets, sai 0 sem publicar nada (quem
  decide o status é o review). `review.yml` não mudou.
- `.board/README.md`, `.board/AGENT_PLAYBOOK.md`, `CLAUDE.md`: integração por
  PR (card → branch → PR → CI + self review → merge só com tudo verde); push
  direto em `main` só para commits que tocam apenas `.board/`.
- `docs/getting-started.md`: a seção "Configuração mínima" é a do AUR-593
  (conflito do merge resolvido com o texto do `main`), mais uma linha
  apontando a configuração do próprio AurumCode.
- `tests/acceptance/AUR-591.sh`: seletores `all`, `AC-003`, `MUT-001`, `MUT-002`.

## Correções vindas da PR #87

- **CI `Build and test in OCI` vermelho** (TestAUR548*, TestAUR567GateLine…,
  TestAUR572Conclusive…, TestAUR575SAST…: exit 1, "LLM quality review did
  not run"): reproduzido na imagem `golang:1.27.1-alpine3.24` do CI só com
  `bash`; com `bash git` o mesmo `go test` passa. Causa: desde o AUR-593 os
  scanners mapeiam as linhas adicionadas com `git diff`, e sem git o scan é
  inconclusivo. Os comandos do job passaram para `scripts/ci/build-test.sh`
  (POSIX sh, instala `bash git` quando faltam) e `scripts/ci/race.sh`
  (imagem bookworm, que já traz git), chamados por `sh`/`bash scripts/ci/...`
  sem `sh -c` longo. O script completo passou na imagem do CI.
- **Auditoria e SARIF não gravados** (`audit_write_failed`/`sarif_write_failed:
  permission denied`): reproduzido localmente. O container roda como root,
  mas o arquivo montado ficava no `/tmp` do container (sticky e gravável por
  todos) e era de outro uid (o do runner); com `fs.protected_regular` o
  `open(O_CREAT)` falha com EACCES mesmo para root. `review.yml` agora monta o
  diretório `${RUNNER_TEMP}/aurumcode-out` em `/aurumcode-out` (fora de
  `/tmp`), grava auditoria, SARIF e saída do changelog ali, devolve os
  arquivos ao uid do runner com um `chown` no fim e mantém o código de saída
  do review. Na PR, a autorrevisão passou a gravar os dois artefatos.
- **"go mod download failed"**: não houve falha. A linha aparece no log só
  porque o GitHub imprime o script do passo antes de executá-lo; nenhum
  `##[warning]` foi emitido, e o govet concluiu (a revisão chegou a um achado,
  não a `lint_*` inconclusivo).
- **Achado SCR-001 em `ci.yml:52`** (`sh -c` com sequência longa como
  command injection): a string não interpola nenhuma entrada externa (nem
  `${{ github.event.* }}`, nem variável do PR); é texto fixo do workflow. Como
  insumo de realimentação da regra: um `sh -c` com literal fixo, sem
  expressão do GitHub nem variável controlada pelo PR, não é injeção. O
  refactor foi feito mesmo assim (scripts versionados). A linha antiga
  `sh -c 'npm install ... node tests/docs/mkdocs.test.cjs'` do job de
  documentação não foi alterada por esta PR e ficou: o aceite do AUR-588
  exige o texto `node tests/docs/mkdocs.test.cjs` dentro do `ci.yml`.
- `scripts/ci/` está fora dos `paths` do card; criado por pedido do
  coordenador.
- Pré-existente, não corrigido: `tests/acceptance/AUR-496.sh` AC-003 já falha
  em `main` (`runs-pr-code`) por causa do passo de prefetch de módulos do
  AUR-593.
