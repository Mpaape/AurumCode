# AUR-591: o Aurum revisa o Aurum por PR, com configuração mínima e skills de convenção

## Medido antes (base b29ca936)

- `.aurumcode/config.yml` só declarava `review.language: pt-BR` e
  `ignore: tests/**`: sem `gate`, sem scanners, sem deliberação, sem skills.
  `.aurumcode/skills/` não existia.
- `.github/workflows/code-review.yml` chama `./.github/workflows/review.yml`
  (check obrigatório de `main`: `review / Review pull request`). Os secrets
  `LLM_API_KEY`/`LLM_BASE_URL` existem no repositório; a última execução
  (2026-10-02, PR do dependabot, sem secrets) falhou no passo "Check provider
  configuration" sem publicar `aurumcode/policy-gate` com o motivo.
- Os cards eram integrados por merge local e push direto em `main`.
- Medido com o binário da base (container `go-shared`): uma skill em
  `.aurumcode/skills/<nome>/SKILL.md` **chega ao prompt**, mas um achado que
  a cita (`tamanho#...` ou `SKILL#...`) é descartado (`1 citing an unknown
  rule_id`). Regras citáveis vêm só de `review.context.skills`, com id
  `<nome-do-arquivo>#<slug>`; listado, o `SKILL.md` gera `SKILL#<slug>` e o
  achado reprova o gate (rc 3).
- Medido na imagem do produto construída deste worktree
  (`aurumcode-review:aur591`, a mesma receita do `review.yml`), primeiro num
  repositório de um arquivo e depois **sobre a árvore real** (clone do
  worktree, fixture de modelo sem achados, `review --base`):
  - `govet` ligado: `lint_unavailable` em toda revisão (a imagem não traz
    `go`) → inconclusivo → bloqueio.
  - `semgrep` (árvore inteira, `p/security-audit` + `p/owasp-top-ten`):
    `sast_invalid_output`, porque o relatório traz 13 erros de parse nível
    `warn` (scripts bash, `action.yml`, locks YAML), e 9 achados `ERROR` em
    arquivos que a PR não tocou (Dockerfiles, `demo/bad-code.go`,
    `secrets: inherit` do `code-review.yml`). Ligado, bloquearia toda PR.
  - `gitleaks` (intervalo da PR): sem achados nem inconclusivo.
  - Num intervalo que toca `docs/assets/capturas/capturas.json`: achados
    `analysis/hardcoded-secret` (as capturas reproduzem os canários dos
    tutoriais) → `docs/assets/capturas/**` entrou no `ignore`.
  - **Cobertura parcial**: um arquivo oculto por `ignore` (ex.:
    `tests/acceptance/AUR-591.sh`) ou um binário (PNG das capturas, mesmo sob
    caminho ignorado) conta como cobertura parcial (`partial_coverage`), que
    com `inconclusive: block` reprova. O gate imprime só o motivo de maior
    rank: na primeira medição ele estava escondido atrás do `sast_*`.

## O que mudou

- `.aurumcode/config.yml` (27 linhas úteis, comentado): `review.language`,
  `review.context.skills` com as seis skills, `ignore: tests/**`,
  `gate: {fail_on: [error], inconclusive: block}`,
  `quality_gates.scanners` com `gitleaks` (`required: true`), `semgrep` e
  `govet` **declarados com `enabled: false`** (ver Decisões),
  `ignore` com `tests/**` e `docs/assets/capturas/**`, e
  `deliberation` ligada com `max_rounds: 3`, `max_cost_tokens: 60000`,
  `per_tool_timeout_seconds: 120`.
- `.aurumcode/skills/<nome>/SKILL.md` (formato do AUR-565, `paths` entre
  aspas), uma por convenção, cada regra com id próprio, exemplo de violação e
  de correção:
  - `arquitetura`: `ARQ-001` lógica em `internal/`, `cmd/` só monta (warning).
  - `tamanho`: `TAM-001` função ≤150 linhas, `TAM-002` arquivo ≤400 (error).
  - `sem-numero-de-card`: `CARD-001` sem id de card em código/doc de pacote (warning).
  - `repo-publico`: `PUB-001` sem empresa/domínio interno/repo privado,
    `PUB-002` sem segredo (error).
  - `sem-bool-exportado`: `BOOL-001` sem parâmetro `bool` em função exportada (error).
  - `gate-fail-closed`: `GATE-001` erro/ausência/dúvida nunca aprova (error).
  Ids citáveis: `SKILL#arq-001-logica-fica-em-internal-cmd-so-monta`,
  `SKILL#tam-001-funcao-com-no-maximo-150-linhas`, etc. As regras
  subjetivas (`ARQ-001`, `CARD-001`) ficam em `warning` (publicam sem
  reprovar); as objetivas têm `severity: error` como piso.
- `.github/workflows/code-review.yml`: comentário explicando que, num
  `pull_request`, `job.workflow_sha` do `review.yml` local é o commit de merge
  da PR (o binário que revisa é o da PR); novo job paralelo `provider`
  (sem `needs`, porque check pulado conta como aprovado) que, sem
  `LLM_API_KEY`/`LLM_BASE_URL`, publica `aurumcode/policy-gate` = `failure`
  com o motivo e sai 1; com os secrets, sai 0 sem publicar nada (quem
  decide o status é o review). `review.yml` não mudou.
- `.board/README.md`, `.board/AGENT_PLAYBOOK.md`, `CLAUDE.md`: integração por
  PR (card → branch → PR → CI + self review → merge só com tudo verde); push
  direto em `main` só para commits que tocam apenas `.board/`.
- `docs/getting-started.md`: seção "Configuração mínima" (8 linhas que o
  consumidor copia: idioma, gate, gitleaks obrigatório).
- `docs/configuration.md`: como uma skill de diretório vira regra citável
  (listar em `review.context.skills`; ids `SKILL#<slug>` únicos).
- `tests/acceptance/AUR-591.sh`: seletores `all`, `AC-003`, `MUT-001`, `MUT-002`.

## Decisões e pendências

- **Bloqueio de merge a decidir pelo coordenador (lacuna do produto, fora
  dos `paths`)**: com a configuração pedida (`ignore: tests/**` +
  `inconclusive: block`), a revisão deste próprio intervalo termina rc 1
  `partial_coverage` só porque `tests/acceptance/AUR-591.sh` foi ignorado.
  Depois do merge, **toda PR de card** (todas adicionam
  `tests/acceptance/AUR-NNN.sh`) e toda PR com capturas PNG fica vermelha no
  self review. Medido: a mesma configuração sem a linha `tests/**` sai rc 0
  neste intervalo (mais cobertura; canários de teste passam a exigir exceção
  do AUR-520 com dono e validade), mas não resolve os PNG. `inconclusive:
  warn` não foi adotado: transformaria falha de provedor e scanner ausente
  em aprovação, contra a GATE-001. Correção certa: card de produto para que
  caminho declarado em `ignore` (e binário sob ele) não conte como cobertura
  parcial, ou conte só sob opção explícita.
- **Semgrep desligado**: varre a árvore inteira e recusa avisos de parse
  (medido acima). Fica declarado com `enabled: false` até um card filtrar o
  Semgrep por linhas alteradas e tolerar avisos `warn`.
- **govet desligado**: ligado, ele bloquearia toda PR (`lint_unavailable`)
  até a imagem do review trazer `go` e um cache de módulos. Fica declarado,
  validado pelo Parse estrito, com `enabled: false` e o motivo no comentário.
  Ligar é um card próprio (imagem do review com toolchain Go).
- **Skill de diretório não citável sem listagem**: lacuna do produto (fora
  dos `paths` e um non-goal deste card). Contornada listando os `SKILL.md`;
  efeito colateral medido: a skill aparece duas vezes no prompt.
- **Binário de `main` como referência** (Outcome item 4): não feito. Um
  segundo chamador publicaria um segundo `aurumcode/policy-gate` no mesmo
  contexto, e o último a terminar venceria. Fica para um card que defina um
  contexto de status próprio para a referência.
- A PR deste card é revisada com a configuração e as skills de `main`
  (base), não com as novas; o novo `code-review.yml` vale já (workflow vem do
  merge ref). Por isso a AC-002 exige uma segunda PR, aberta depois do merge.

## Roteiro do coordenador (AC-001, AC-002, AC-004)

Pré-requisito: secrets `LLM_API_KEY`, `LLM_BASE_URL` e variável `LLM_MODEL`
presentes (`gh secret list; gh variable list`).

AC-001 e AC-004 (PR deste card):

```bash
cd /home/paape/repos/AurumCode
git push -u origin card/AUR-591
gh pr create --base main --head card/AUR-591 \
  --title "AUR-591: o Aurum revisa o Aurum por PR" \
  --body "Card AUR-591. Spec: docs/specs/AUR-591.md"
N=$(gh pr view card/AUR-591 --json number --jq .number)
gh pr checks "$N" --watch
HEAD=$(gh pr view "$N" --json headRefOid --jq .headRefOid)
gh api "repos/Mpaape/AurumCode/commits/$HEAD/statuses" \
  --jq '.[] | select(.context=="aurumcode/policy-gate") | [.state,.description] | @tsv'
gh pr view "$N" --json reviews,comments --jq '[.reviews[].state, (.comments|length)]'
# o binário revisor é o da PR: o SHA do "Checkout AurumCode" é o merge commit
gh api "repos/Mpaape/AurumCode/pulls/$N" --jq .merge_commit_sha
RUN=$(gh run list --workflow code-review.yml --branch card/AUR-591 -L1 --json databaseId --jq '.[0].databaseId')
gh run view "$RUN" --log | grep -A3 'Checkout AurumCode' | grep -E 'ref|sha' | sed -n '1,5p'
# merge só com tudo verde; --merge preserva os SHAs do Delivery record
gh pr merge "$N" --merge --delete-branch
git fetch origin && git merge-base --is-ancestor <sha-do-delivery> origin/main && echo ancestor
```

Registre na spec/card: URL da PR, estado do review, linha do
`aurumcode/policy-gate`, e o `merge_commit_sha` comparado ao SHA do checkout.

```bash

git fetch origin && git switch -c teste/convencao-funcao-longa origin/main
mkdir -p internal/sondaconvencao
```

Atenção: a PR de teste só toca `internal/sondaconvencao/longa.go` (nada
ignorado, nada binário), então não cai em `partial_coverage`. Qualquer PR
que toque `tests/**` ou PNG cai, até a decisão acima.

Pendente: o teto `max_cost_tokens: 60000` da deliberação não foi conferido
contra o uso real de tokens de uma revisão (o provedor de fixture não chama
ferramentas); conferir na auditoria da PR do AC-001.

Se o modelo não citar a skill, a AC-002 não está provada (não reabra com
outro texto até passar: registre o parecer recebido). MUT-001 real, opcional:
na mesma branch de teste, um commit que apaga
`.aurumcode/skills/tamanho/SKILL.md` não muda o parecer (a configuração vem
da base); por isso o MUT-001 é provado localmente no aceite.
