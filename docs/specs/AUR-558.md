# AUR-558 -- cmd/aurumcode organised by responsibility, with a structural guard

A refactor with no change of behavior, continuing AUR-557.

## What moved

### Decision logic into `internal/gate`

| Before (`cmd/aurumcode`) | After (`internal/gate`) |
| --- | --- |
| `evaluateGate`, `severityRankOf`, `effectiveSeverityRank`, origin constants (`policygate.go`) | `policy.go`: `EvaluateGate`, `SeverityRankOf`, `EffectiveSeverityRank`, `OriginPolicy`, `OriginRepo` |
| `matchException` and its lines/markers (`aur520.go`) | `exceptions.go`: `MatchException`, `TruncateToUTCDate`, `AcceptedExceptionLine`, `ExpiredExceptionLine`, `ExceptionsConfigured`, `RepoIdentityUnavailableNotice` |
| `applyAnalysisGate`, `analysisIssuesForGate`, `gateSASTIssues`, `foldGateSources` (`gate_sources.go`) | `sources.go` |
| `applySASTGate` (`aur548.go`) | `sast.go`: `ApplySASTGate` |
| `applyAnalysisDataGate` (`aur533.go`) | `analysisdata.go` |
| `applyDTrackGate`, `mergeDTrackGate`, `wrapWriterWithFilter` (`aur550.go`) | `dtrack.go` |
| `reuseOrStoreGateVerdict`, the verdict key and store (`aur524.go`) | `verdict.go` |
| `applyGateOutcome` (`main.go`) | `outcome.go`: `ApplyOutcome` |
| the seven contributor adapters (`review_gate_contributors.go`) | `contributors.go`: exported types with fields |

What the gate needs from the command is injected, not imported: the prompt
digest (`VerdictReuseContributor.PromptDigest`), and the review-context cache
key (`VerdictKeyInputs.ContextKey`, a lazy `func() string` so a nil provider is
only touched when a verdict can be reused, as before). The binary identity
(`binaryIdentity`, which reads the command's `version`) stays in
`verdict_inputs.go` and arrives in `VerdictKeyInputs.BinaryIdentity`.

`review_gate.go` is the only production file of `cmd/aurumcode` that imports
`internal/gate`. It declares the pipeline (`assembleGatePipeline`) and the
command's names for the package (`gateDecision`, `gateRun`, `gateOriginRepo`,
and so on); every other file uses those names.

`generateReview` left `pr.go` for `review_pr_generate.go`; `applyGateOutcome`
left `main.go` for `gate.ApplyOutcome`.

## Structural coverage stays in the analyses phase

`applyStructuralCoverage` (`structural_coverage.go`) runs before the
inconclusive reason is ranked, and its notice must keep its place in
`Limitations` ahead of the changelog and policy notices. A pipeline
contributor runs after the analyses and the reason ranking, so moving it there
would reorder the published `Limitations`. It is therefore not a contributor.

## Tests

The tests that call the moved functions stay in package `main` and now call
the `internal/gate` API (`igate.EvaluateGate`, `igate.MatchException`, ...):
the assertions are unchanged, only the callee's package. They did not move
into `internal/gate` because the acceptance scripts select them by name in
`./cmd/aurumcode`, and moving them would change every selector. Files:
`aur520_test.go`, `aur521_test.go`, `aur524_test.go`, `aur533_test.go`,
`aur538_test.go`, `aur548_test.go`, `aur550_test.go`, `policygate_test.go`.
`passes_test.go` reads `verified_checkout.go` instead of `aur536.go`.
