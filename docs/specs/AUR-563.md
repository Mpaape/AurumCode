## Decisoes

- **Mesmo contrato do AUR-561.** Blocos `<!-- arquivo: PATH -->` identicos aos
  arquivos; `<!-- saida: caso -->` com linhas literais do `out/`;
  `--check` por `grep -F`; linhas `RESULTADO:` sao conclusao do script.
- **Nenhum digest digitado a mao.** O unico lugar com digests e
  `demo/gate-corporativo/images.lock`; `compose.yml` do Dependency-Track usa
  `${DTRACK_IMAGE}`/`${POSTGRES_IMAGE}` exportados pelo `run.sh` a partir dele.
  O Semgrep e o da imagem do produto (versao de `.board/bootstrap/locks/scanners.yml`).
- **Provedor sempre fixture; aurumcode sempre na imagem do produto**, com
  `--user "$(id -u):$(id -g)"`. Rede: `none`, exceto `sbom-dependency-track`
  (`--network host`: o gate so aceita https ou IP de loopback) e
  `dados-de-analise` (um servidor falso que atende como a API do GitHub dentro
  do mesmo container, com CA de demonstracao gerado a cada execucao em `.estado/`).
- **`api.github.com` no aceite.** O produto fixa esse endereco para o
  `analysis_data` (nao ha variavel que o troque); o AC-003 o admite na lista de
  dominios, junto dos reservados. E a API publica do GitHub, nao dado interno.

## Achados sobre o produto

1. **Corrida nas metricas do Dependency-Track (grave).** O gate le as metricas
   assim que o servidor responde `processing: false`, e a avaliacao de politica
   pode terminar depois. Num servidor novo, a primeira revisao com lodash 4.17.15
   leu `policy_violations=0` e **aprovou o que a politica reprova** (2 de 2
   vezes); em outra execucao, logo apos trocar a dependencia, leu a violacao
   antiga e reprovou. O tutorial contorna com um aquecimento e a funcao
   `dt_assenta` (linha `assentamento:` nos `out/`) e declara que e contorno do
   script. Causa nao investigada; vale um card (reler ate estabilizar).
2. **`--semgrep-bin` nao existe**: o Semgrep e resolvido pelo `PATH`
   (`cmd/aurumcode/aur548.go`). O caso de falha poe um Semgrep falso a frente no `PATH`.
3. O `check_id` leva o caminho do arquivo de regras (`semgrep:regras.demo-sem-eval`
   no repositorio; `semgrep:policy.regras.demo-sem-eval` sob politica em `/policy`).
   `rule_packs` local e relativo ao repositorio; sob politica precisa ser absoluto.
4. Com o SAST inconclusivo o parecer ainda diz `No issues found.`; so as linhas
   `SAST ... inconclusive` mostram o estado real.
5. O endereco da API do GitHub do `analysis_data` e fixo no binario; so o seam de
   teste Go o troca. `AURUMCODE_GITHUB_API_URL` vale so para o cliente de PR.
6. `aurumcode sign` valida o arquivo do bundle, nao o exit do Cosign: Cosign que sai
   0 sem bundle falha (`cosign exited 0 but wrote no signature bundle`). Sem
   `quality_gates.supply_chain`, `sign` sai 0 sem assinar. Falha de assinatura
   usa o exit 1 generico (`exitQualityNotReviewed`).
7. `xbom --help` imprime so a linha de uso (sem lista de flags); a politica central
   precisa de `.aurumcode/config.yml` valido mesmo para `xbom`; um catalogo do
   repositorio ou da politica substitui o embutido por inteiro.
8. Resultado inconclusivo de `analysis_data` ou do Dependency-Track deixa o
   veredito em `Comment`, nunca `Approve`, com `warn` ou `block`.
9. O Trivy lista `package-lock.json@None` como componente de arquivo sem versao.

## Limites (o que NAO foi demonstrado)

- Pacote do registry do Semgrep com sucesso (`p/...`): exige rede; o caso prova so
  a falha sem rede (e nao distingue timeout de recusa de rede).
- `max_critical`/`max_high`: o Trivy roda com `--scanners license` e o servidor nao
  tem feeds, entao critical/high ficam 0; so `policy_violations` e provado.
  `dtrack_unreachable`, `dtrack_http_error` e 403 nao foram executados.
- Timeout do Dependency-Track: provado contra um servidor falso (sempre
  `processing: true`), nao contra o Dependency-Track real.
- Assinatura keyless, upload do artefato e `verify-blob` keyless: so conferencia
  estatica (exigem o OIDC do GitHub Actions). Assinatura de imagem real (exige registry).
- xBOM: envio ao Dependency-Track, modelo real, prompt sobrescrito pela politica.
- `analysis_data`: GitHub real, release imutavel, repositorio privado com token,
  `analysis_data_invalid`, download da copia OSV. O workflow agendado so e conferido
  estaticamente. Nao ha runner real do GitHub em nenhum tutorial.
