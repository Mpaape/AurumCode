# AUR-538: provas que faltaram no gate do AUR-519

Fecha oito lacunas de prova não bloqueantes deixadas pelas revisões do
AUR-519/520, sem mudar o comportamento do gate (ver Non-goals do card).

## AC-001 — veredito nunca lê Approve sob bloqueio

Com `--base`, uma fixture sem nenhum achado (nenhum segredo fixo no
código) e `gate: inconclusive: block`, o relatório local nunca mostra
`**Verdict:** Approve`, para veredito do modelo `""` ou
`"changes_requested"`. O mecanismo real é a marca
`result.Metadata[prompt.PolicyGateWithheldKey] = "true"` (main.go), lida
por `formalReviewEvent`/`canonicalVerdict` (pr.go/passes.go) — nunca o
campo `result.Verdict` que o modelo controla. Um controle positivo prova
que a mesma fixture, sem gate, publica Approve normalmente: a ausência de
"Approve" sob bloqueio só pode ser explicada pela marca, nunca por uma
propriedade incidental da fixture (ver AC-003).

## AC-002 — a marca retida não pode ser forjada

O parser (`internal/prompt/parser.go`) descarta
`metadata.policy_gate_withheld` de toda resposta do modelo, antes de
qualquer leitura própria do motor — um modelo nunca escreve essa marca.

## AC-003 — assertiva decorativa corrigida

`TestAUR519GatePartialCoverageInconclusiveWarns` usava `coverageFixture`
(AUR-476), cujo `app.go` sempre embute um segredo fixo para um propósito
não relacionado. Passou a usar `aur538CleanFixture`, sem nenhum conteúdo
que pareça segredo, para que a assertiva só possa ser explicada pelo
rebaixamento do veredito do próprio gate.

## AC-004 — árvore do HEAD ilegível é inverificável

Sem binário git, um checkout com metadados git reais mas cujo objeto da
árvore do HEAD foi apagado (perfil selado: apenas objetos soltos) é
declarado `codebaseContextReasonUnverifiable` — nunca limpo — tanto com
quanto sem `git` no PATH. Testado chamando `verifiedCleanCheckoutReason`
diretamente, isolando exatamente o erro de `TrackedFiles`.

## AC-005 — identidade do repositório indisponível

Com `--base` e sem remoto `origin` configurado, uma exceção que
corresponderia exatamente ao achado falha fechada (o gate reprova e o
aviso de identidade indisponível aparece). Sem nenhuma exceção
configurada, o aviso não aparece.

## AC-006 — exceção ativa vence a vencida

`matchException` (aur520.go) agora prefere o primeiro match ATIVO,
independente da ordem na lista — uma renovação (entrada vencida mantida
para histórico, seguida de uma nova com validade futura) aplica a
renovada.

## AC-007 — descrição do status respeita o limite do GitHub

A descrição do commit status `aurumcode/policy-gate` é limitada a 140
caracteres (limite do GitHub), contados por rune (nunca por byte, para
não corromper um caractere acentuado), sempre com o resultado primeiro
(`falha`/`inconclusivo`/`aprovado`) e, quando truncada, terminando em uma
única elipse. Um achado real é ordenado antes do motivo de
inconclusividade dentro desse corte (`orderedGateReasons`), para ter a
melhor chance de sobreviver ao limite. O corpo completo do review nunca é
afetado — só este campo publicado.

## AC-008 — seletores do AUR-520.sh exigem seus próprios testes

Cada seletor de AC em `tests/acceptance/AUR-520.sh` (não só `all`) agora
confere que TODOS os seus próprios testes nomeados aparecem com
`--- PASS:` no log — nunca apenas "algum teste passou".
