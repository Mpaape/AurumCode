# AUR-360 — Fixar Go toolchain e módulos

## Purpose

Pins the Go toolchain version and the exact, immutable module set the
repository depends on: `go 1.21` (from `go.mod`), the module path
`github.com/Mpaape/AurumCode`, a recomputed SHA-256 digest of `go.mod` and of
`go.sum`, and, for every module recorded in `go.sum`, its immutable version
plus its module-content checksum (`h1:...`, the standard Go module checksum
already present in `go.sum`). `tests/acceptance/AUR-360.sh` verifies the
sealed lock is present, well-formed, free of mutable references, and
cross-checked field-by-field against the real `go.mod`/`go.sum` it claims to
pin — it never downloads or resolves a module (see Non-goals below and in
the card).

## Codes

Typed dispositions `tests/acceptance/AUR-360.sh::AC-001` actually emits on
stderr as `AUR-360/AC-001/<code>` (exit `1`), each now produced by a
`go.mod`/`go.sum` cross-check, not a structural check alone:

| Code | Trigger (as implemented) |
|---|---|
| `go_lock_mismatch` | `.board/bootstrap/locks/go.yml` is absent or not a regular file; `go_version` differs from `go.mod`'s `go` directive; a module `go.sum` records is unpinned, version-drifted, or pinned with the wrong checksum; or the lock pins a module `go.sum` does not record. |
| `source_integrity_error` | `.board/bootstrap/locks/go.yml` is a symlink; or the recomputed SHA-256 of `go.mod` or of `go.sum` no longer matches the lock's own `go_mod_sha256`/`go_sum_sha256` field (the lock's declared "source hash lock" no longer holds). |
| `invalid_lock_or_manifest` | Missing the exact line `schema: bootstrap-lock-v1` or `card: AUR-360`; no `sha256:[0-9a-f]{64}` pattern anywhere; a required field (`go_version`, `module`, `go_mod_sha256`, `go_sum_sha256`, `module_count`) absent or empty; `module_count` non-numeric, zero, or not equal to the number of `module_<n>_path:` lines actually present; or a `module_<n>_path`/`module_<n>_version` pair missing or duplicated. |
| `mutable_reference` | The file contains a bare `latest` token or an `@main`/`@master`/`@HEAD`-style reference. |
| `input_limit_exceeded` | `.board/bootstrap/locks/go.yml` exceeds `4096` bytes, or `module_count` exceeds `256` — checked before any per-module parsing, so an over-limit `module_count` never requires fabricating that many module lines to observe. |
| `module-path-mismatch` | The lock's `module:` field differs from `go.mod`'s `module` directive (MUT-001's exact scenario: the module path changed in the snapshot after the source hash was locked, while `go_mod_sha256` still matches the untouched `go.mod`). |
| `module-checksum-missing` | A module `go.sum` records is pinned in the lock with the correct path and version but an empty/absent `module_<n>_checksum` (MUT-002's exact scenario: the checksum removed, the version kept). |

`unknown-selector` (exit `64`) is emitted for any first argument outside
`AC-001`, `ContractAUR360`, `IntegrationAUR360`, `E2EAUR360`; all four
accepted selectors currently run the identical body above.

### Known gap — round 2 closure

Round 1 sealed a structural-only oracle (three checks: schema line present,
some `sha256:` pattern present, no mutable token) that never read `go.mod`
or `go.sum` and could not observe MUT-001 or MUT-002 at all — both mutations
left the script's exit at `0`. Round 2 replaces the oracle body with
`verify_go_lock()`, which parses `.board/bootstrap/locks/go.yml` field by
field and cross-checks `go_version`, `module`, `go_mod_sha256`,
`go_sum_sha256`, and every `module_<n>_path`/`version`/`checksum` triple
against the real, materialized `go.mod`/`go.sum` (a bijection both ways: no
`go.sum` module unpinned, no lock entry phantom), before any other consumer
of the domain runs. This closes every gap round 1 recorded:

- **Module path / go_version drift, per-module version/checksum drift**:
  now detected — `module-path-mismatch`, `go_lock_mismatch` (go_version),
  `go_lock_mismatch` (per-module version/checksum drift or an unpinned
  real module), `module-checksum-missing` (checksum removed but version
  kept). Reproduced live against the real lock for MUT-001 and MUT-002
  (see the acceptance evidence for this round), plus one extra mutation of
  the same supply-chain class this round adds: a present-but-*wrong*
  `module_1_checksum` (as opposed to MUT-002's *missing* checksum), which
  is deliberately a distinct disposition (`go_lock_mismatch`, not
  `module-checksum-missing`) because the field is present and parseable —
  only its value is wrong.
- **`input_limit_exceeded`**: now reachable — `module_count` over `256`
  (the `overlimit` fixture) or the lock document over `4096` bytes both
  short-circuit to this code before any per-module parsing.
- **Symlink vs `source_integrity_error`**: a symlinked lock now reports
  `source_integrity_error`, not `go_lock_mismatch`; the same code now also
  covers a `go.mod`/`go.sum` whose recomputed digest no longer matches the
  lock's own `go_mod_sha256`/`go_sum_sha256` ("tamper in the source" per
  the card's `Then` clause — `go.mod`/`go.sum` are the "source" MUT-001's
  own phrasing names, `"...depois do source hash lock"`).

**Residual, documented tension (not closed, by design):** the card's
`Public contract` line enumerates exactly four codes
(`go_lock_mismatch|source_integrity_error|invalid_lock_or_manifest|
input_limit_exceeded`), while `Skeptical mutations` MUT-001/MUT-002 name two
further, more specific literal codes (`module-path-mismatch`,
`module-checksum-missing`) for what is, read one way, the same underlying
"module field drifted from `go.mod`/`go.sum`" condition the `Public
contract`'s `go_lock_mismatch` already covers. `.board/cards` is this card's
own `forbidden_paths` entry, so round 2 cannot edit the card text to
reconcile the two lists; instead it honors the more specific, literally
quoted MUT-001/MUT-002 strings — the two mutations the skeptical approver
actually replays and checks byte-for-byte — as the authoritative
requirement for those two exact scenarios, and keeps `go_lock_mismatch` for
every other drift the `AC-001` `Then` clause groups under that name (whole
go_version drift, per-module version/checksum drift not matching either
MUT's exact shape, and phantom pins). A future card correcting the card
text itself (not this one, and not this file) would need to either fold
`module-path-mismatch`/`module-checksum-missing` into the four-code
contract list explicitly, or drop the two literal strings from the
Skeptical mutations prose.

## Non-goals (restated from the card)

This card never runs `go mod tidy`, `go mod download`, `go get`, or any
other command that resolves, updates, or promotes a Go module version. Every
value in `.board/bootstrap/locks/go.yml` is read from the `go.mod`/`go.sum`
already committed in this repository.
