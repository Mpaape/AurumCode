`stage_source()` copiava uma lista enumerada de subpacotes: faltavam
internal/artifacts, internal/dtrack, internal/gate, internal/grammar,
internal/reviewprofile, internal/sbom, internal/supplychain e internal/xbom,
adicionados ao produto depois da lista. Sem eles, o Go tenta resolve-los como
modulo e o GOPROXY=off recusa. Nao ha modulo externo faltando; go.mod/go.sum
nao mudam.

Corrigido o build, `IntegrationAUR439` mostrou uma segunda camada de
defasagem, so em `tests/integration/AUR-439.go` (o e2e ja estava alinhado):

- O fake respondia o DIFF em `GET /repos/dono/projeto/pulls/42` para qualquer
  `Accept`. Desde o AUR-504, `--check` ancora o status no `head.sha` dos
  metadados JSON desse endpoint; sem ele o produto falha fechado
  (`decoding pull request metadata`, 0 status POST).
- As respostas de modelo sinteticas nao traziam `impact`, `evidence` e
  `verification`; o gate de escopo e evidencia descarta o achado (grave virava
  sucesso).
- O contrato de zero achados no `--pr` e a linha `0 comentario(s)
  publicado(s)` mais o status; `No issues found.` e do `--base` (AUR-490), e o
  comentario-resumo sempre e postado (1 status + 1 resumo).

## Correcao

`tests/acceptance/AUR-439.sh`: `copy "$root" cmd internal pkg` (inteiros, nunca
lista enumerada) e `GOCACHE` respeitado quando ja exportado. Nenhuma
asserção, mutação, selector ou exit code mudou.

`tests/integration/AUR-439.go`: o fake devolve o diff quando o `Accept` pede
diff e, senao, `{"number":42,"title":"t","body":"b","head":{"sha":...}}` com o
head definido por subteste (o mesmo valor do GITHUB_SHA que o teste ja
afirmava no caminho do status); fixtures com impact/evidence/verification;
o subteste sem SHA espera a recusa `head SHA` (AUR-504, igual ao e2e); zero
achados espera a linha de resumo e 2 POSTs. As mesmas propriedades continuam
afirmadas (grave nunca sai 0, estado failure/success, um unico status, token
somente-leitura sem POST, determinismo).
