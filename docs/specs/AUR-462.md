# AUR-462 — the security passage sees Node's exec() and innerHTML shapes

## Command

```
aurumcode review --base <ref> [--fail-on <level>] [--modelo <nome>] [--seguranca]
```

Same command AUR-435/AUR-442/AUR-461 published. This card does not add a
flag or change the output shape; it extends what `--seguranca`'s
deterministic pass matches, in `internal/review/rules/security.yml`.

## The measured defect (2026-08-14)

Run against a JavaScript file carrying five planted defects, the pass
found the secret, the second secret, and the SQL injection, and missed
two: `exec("ping -c 1 " + host)` and `innerHTML = userInput`.

Cause 1: `security/command-injection`'s pattern was
`(?i)\b(system|popen|exec[lv]p?e?|subprocess\.(run|call|Popen))\s*\(.*["']\s*\+`.
`exec[lv]p?e?` requires an `l` or `v` right after `exec`, so it matches
`execl`, `execv`, `execve` (C, Python) and never the bare `exec(` of
Node's `child_process` — the canonical Node shape. `execSync` and
`spawn(..., {shell: true})` escaped for the same reason.

Cause 2: `security/xss` was one of the five catalog rules with no
`pattern` at all (a deliberate AUR-442 scope decision), so it never
matched anything.

## The fix

Both rules keep their id (the AUR-461 mirror in
`internal/prompt/rulecatalog.go` compares ids in both directions against
this catalog, so no id was added or renamed):

- `security/command-injection` gained two alternatives, additive to the
  original C/Python/subprocess branch (byte-for-byte unchanged, so AC-003
  regresses clean): a bare `exec(`/`execSync(` call carrying the same
  quote-then-`+` concatenation shape as every other branch, and a
  `spawn(...)` call whose options carry `shell: true` (flagged on the
  option alone, since `shell: true` hands the whole argument list to a
  shell regardless of whether the command itself is concatenated).
- `security/xss` gained a pattern: a bare, unescaped identifier written
  into `innerHTML`/`outerHTML`, into `document.write(...)`, or into
  React's `dangerouslySetInnerHTML`'s `__html` key.

## AC-002: the false-positive discipline

Three shapes are excluded structurally, not by a lookahead (Go's RE2 has
none):

- `exec(["ping", host])` (Node's argv form, no shell): has no quote
  followed by `+` anywhere in the call, so neither command-injection
  alternative matches.
- `innerHTML = "<b>Static content</b>"` (a literal): every xss
  alternative requires the assigned/sink value to *start* with an
  identifier character (`[A-Za-z_$]`); a value opening with `"`, `'`, or a
  backtick never matches.
- `// exec is dangerous when combined with string concatenation.` (a
  comment mentioning "exec"): has no `exec(`/`execSync(` call shape and no
  quote-then-`+`, so it matches nothing.

## AC-003: regression

`security/sql-injection`, `security/hardcoded-secret`, and the original
C/Python/subprocess branch of `security/command-injection` are untouched
strings; the project's own committed Python fixture
(`tests/fixtures/review/vuln/repo.git`) still reports exactly the same
`src/db.py:8` `security/sql-injection` finding it reported before this
card.

## Why no fixture directory

This card's `paths` own `internal/review/rules` and its own
unit/integration/e2e/acceptance programs, not a fixtures directory. So no
Node source is committed to the repository tree: each test program
(`tests/unit/AUR-462.go` as a synthetic diff; `tests/integration/AUR-462.go`
and `tests/e2e/AUR-462.sh` as an ephemeral `git init`/`git commit`
repository; `tests/acceptance/AUR-462.sh` the same, per case) materializes
the identical 27-line Node source at run time instead.

## Non-goals (unchanged from the card)

- No AST/semantic analysis: the pass stays a deterministic line matcher.
- No loosening of existing patterns to chase coverage.
- No promise of the remaining patternless rules (`path-traversal`,
  `weak-crypto`, `insecure-random`, `missing-auth`); the pass still
  declares how many of the 8 catalog rules it actually applies.
