    AUR-593: ergonomia medida pelo Aurum no Aurum

    Medido antes (base f9a4f751)

    Ao ligar o Aurum no próprio repositório (AUR-591) com a configuração mínima:

    1. Cobertura parcial por ignore e binário. mergeReviewCoverage (cmd/aurumcode/review_coverage.go) somava os caminhos do ignore e todo arquivo filtrado (binário, gerado, grande demais) em uncovered(); partial() ficava verdadeiro e, com inconclusive: block, a revisão saía partial_coverage. applyStructuralCoverage ainda retinha a aprovação por qualquer binário. No --pr, um binário sem patch entrava no prompt e era contado também como "omitido pelo limite de tokens".
    2. Semgrep na árvore inteira. Medido na imagem do produto (semgrep 1.172.0, p/security-audit + p/owasp-top-ten) sobre a árvore real: 23 resultados, a maioria em arquivos que nenhuma PR de card toca (Dockerfiles, demo/bad-code.go, dependabot.yml), e 13 erros nível warn (5 Syntax error, 8 PartialParsing). Causa do sast_invalid_output: (a) o campo type de um PartialParsing é um array (["PartialParsing", [...]]) e o adaptador o decodificava como string, então o json.Unmarshal do relatório inteiro falhava ("invalid JSON output"); (b) mesmo decodificado, qualquer entrada em errors tornava o relatório inválido, inclusive um parse recuperado num arquivo que a PR não tocou.
    3. Skill de diretório não citável. Só review.context.skills gerava regras (dynamicRulesFromLocalSkills/RemoteSkills); o catálogo de .aurumcode/skills/<nome>/SKILL.md só mandava texto ao prompt. Listar o arquivo nas duas fontes duplicava o texto, e o id era SKILL#<slug> para toda skill de diretório (colisão entre skills).
    4. govet sem go. A imagem final (alpine) não tinha o toolchain: lint_unavailable em toda revisão.

    O que mudou

    • Cobertura (cmd/aurumcode/review_coverage.go, passes.go, structural_coverage.go, review_pr*.go, internal/analyzer/textdiff.go, internal/i18n/catalog.yml): caminho do ignore e binário (analyzer.NoticeReasonBinary) viram IgnoredPaths, fora de partial(); um arquivo conta uma vez (ignorado vence binário). O aviso de cobertura lista os ignorados mesmo com a revisão completa. Gerado, grande demais, sem patch e orçamento continuam parciais e retêm a aprovação. No --pr, declareBinaries tira o binário do diff antes do prompt (como o --base).
    • Escopo de mudança (internal/scanner/added_lines.go, movido de internal/scanner/govet/diff.go, um lugar só): scanner.AddedLines, LineSet.Keep/Touched, scanner.ErrNoRange. O govet usa o mesmo código. O semgrep (internal/scanner/semgrep) continua varrendo a árvore, guarda só achados em linhas adicionadas, decodifica type cru (json.RawMessage) e só trata como inválido o erro que alcança a mudança: nível diferente de warn, erro sem arquivo, warn em arquivo tocado sem trecho, ou trecho sobre linha adicionada. Sem intervalo revisado: inconclusivo. O semgrep recebe só o safe.directory do ambiente (o git diff roda num checkout de outro usuário no CI).
    • Skills (internal/context/skills/catalog.go, internal/review/skillrules.go, cmd/aurumcode/policygate.go, skill_catalog.go, review_base_analysis.go, review_pr_model.go): o catálogo guarda a camada de cada skill (LayerPolicy/LayerRepository) e expõe Docs(changed); dynamicRulesFromCatalog transforma cada skill selecionada em regras com a origem da sua camada (uma skill do repositório nunca ganha origem de política). ExcludeListed tira do catálogo o SKILL.md que a mesma camada lista em context.skills (texto uma vez). O id de um SKILL.md é <diretório>#<slug> nas duas fontes. No --base o catálogo é montado antes das regras, e as regras entram no digest do catálogo de regras (cache).
    • Imagem (Dockerfile): COPY --from=builder /usr/local/go da imagem golang:1.27.1-alpine3.24@sha256:8a59... (a mesma do build, a do go.mod), PATH, GOPATH=/go, GOMODCACHE=/go/pkg/mod, e o build falha se go version não for go1.27.1. Workflow (review.yml): passo "Prefetch Go modules for the lint engine" (go mod download com GOTOOLCHAIN=local, sem segredos, só com go.mod), cache montado em /go/pkg/mod na review; download que falha é aviso e o govet ligado fica lint_execution_error (fail-closed).
    • Tutoriais: revisao, gate, reaproveitamento e auditoria-sarif usavam um PNG para forçar cobertura parcial; agora usam um arquivo gerado (repo-exemplo/gerado/gerado.go). revisao/falha-nao-revisado ganhou uma terceira parte (terceira parte do caso: PNG + inconclusive: block → exit 0, logo.png (binary) listado). sast/govet-sem-go tira o Go do PATH (a imagem agora o traz). Todos os out/ regravados com a imagem deste worktree; capturas regravadas.
    • Docs: configuration.md (ignore/binário fora da cobertura, escopo do semgrep e dos erros de parse, id de skill de diretório, Go na imagem e prefetch), getting-started.md (seção "Configuração mínima"), architecture.md, tutoriais revisao, gate, qualquer-linguagem, sast.
